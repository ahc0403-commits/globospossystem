# 설계 브리프: 모바일·태블릿 일일 마감 전용 화면

Date: 2026-08-13
Source: 사용자 제공 모바일 Safari 캡처와 현재 리포트 구현 점검
Status: 계획 전용 — 기능 구현·DB 변경·배포하지 않음

## 목표

휴대폰과 태블릿의 리포트 화면에서는 일일 마감 표를 본문에 직접 끼워 넣지 않고, 간단한 진입 카드에서 눌러 전용 전체 화면으로 연다. 넓은 웹 화면은 현재 인라인 표를 유지한다.

- 휴대폰과 태블릿에서는 리포트 본문의 `일일 마감` 진입 카드를 누르면 앱 내부 전체 화면으로 이동한다.
- 전용 화면은 같은 로그인 세션과 선택 매장을 유지하며 시스템/앱 뒤로가기로 리포트에 복귀한다.
- 전용 화면 안에서도 15개 값을 한 행에 압축하지 않고 화면 크기에 맞는 카드형 정보 구조로 표시한다.
- 넓은 웹 화면의 기존 표, 조회, 마감 생성, 잠금 상태와 계산 방식은 변경하지 않는다.
- 기존 Provider, 서비스, `create_daily_closing` RPC, 현금 시재 계산과 저장 데이터 계약을 그대로 사용한다.

## 현황 확인

### 재현된 원인

- `ReportsTab`은 화면 폭이 `1080` 미만이거나 큰 글자 모드일 때 compact 레이아웃을 사용하지만, 이 분기에서도 `_DailyClosingSection`을 그대로 인라인 렌더링한다.
- `_DailyClosingSection`의 헤더와 행은 날짜부터 상태까지 15개 항목을 하나의 `Row` 안에서 `Expanded`로 나눈다.
- 최소 너비, 가로 스크롤, compact 카드 변형이 없어 휴대폰에서는 열당 폭이 수십 px 이하로 줄고 한글과 VND 금액이 글자 단위로 줄바꿈된다.
- 태블릿도 같은 구현을 사용한다. 특히 1024px 가로 화면은 데스크톱 셸의 약 212px 사이드바와 여백을 제외하면 표의 실제 가용 폭이 약 800px 이하이므로 15개 열을 읽기 어렵다.
- 현재 일일 마감 영역은 높이 220의 고정 컨테이너여서 좁은 화면에서 내용 높이가 늘어날수록 탐색성이 더 나빠진다.
- 운영 사이트는 점검 브라우저에 로그인 세션이 없어 내부 리포트의 실데이터 화면까지 진입하지 못했다. 다만 사용자 캡처와 위 레이아웃 코드가 같은 실패 원인을 보여준다.

### 재사용할 부분

- `dailyClosingHistoryProvider(storeId)`의 로딩·오류·빈 상태와 일일 마감 기록 데이터
- 현재 `_createClosing` 흐름, 미리보기, 현금 시재 입력, 중복 마감 방지와 권한 판정
- `DailyClosingRecord`의 합계·차액 계산과 `DailyClosingService`
- 기존 리포트 compact/desktop 분기, 앱 테마, 색상, 카드, 버튼 토큰
- 기존 일일 마감 모델·RPC·계약 테스트

## 화면 계약

### 1. 리포트 진입 영역

- 현재 compact 레이아웃(`width < 1080`)과 큰 글자 compact 레이아웃에서는 15열 표 대신 `일일 마감` 진입 카드를 표시한다.
- 진입 카드에는 화면 목적, 최근 마감일/상태 또는 `마감 기록 없음`, `일일 마감 열기` 버튼만 표시한다.
- 카드 전체와 버튼 모두 같은 전용 화면으로 이동할 수 있고 최소 48dp 터치 영역을 확보한다.
- 넓은 웹(`width >= 1080`, 일반 글자 크기)은 현재 인라인 `_DailyClosingSection`을 그대로 유지한다.

### 2. 휴대폰·태블릿 전용 화면

- 브라우저 새 탭이나 팝업이 아니라 `Navigator.push(MaterialPageRoute(...))` 기반 앱 내부 전체 화면으로 연다. 팝업 차단, 로그인 세션 분리, 매장 ID 유실 위험을 피하기 위한 결정이다.
- AppBar에 `일일 마감`, 뒤로가기, 현재 매장 문맥을 표시하고 본문 전체를 세로 스크롤 가능하게 한다.
- Phone(`<600dp shortestSide`)은 날짜별 1열 카드로 표시한다.
  - 상단: 날짜, 담당자, 마감 상태
  - 주문: 주문/완료/취소
  - 매출: 총매출, 현금, 페이, 카드, 계좌이체
  - 현금 대사: 실제 시재, 차액, 시작 잔액, 마감 상계 총액
  - 하단: 마감 실행 또는 잠금 상태
- Tablet은 날짜별 1열 와이드 카드 안에서 주문·매출·현금 대사를 2~3개 컬럼 그룹으로 배치한다. 화면 방향이 바뀌거나 가용 폭이 좁으면 그룹을 자동 줄바꿈한다.
- Loading, error, empty, open, closed 상태와 기존 행별 action key의 의미를 유지한다.
- 긴 담당자명, 큰 VND 금액, KO/VI/EN 문구가 글자 단위로 쪼개지지 않아야 한다.

### 3. 현금 시재 입력

- 기존 권종, 수량, 합계, 차액 계산과 제출 동작은 변경하지 않는다.
- Phone에서는 입력 폼을 전체 화면 또는 화면 높이에 안전한 스크롤형 다이얼로그로 표시한다.
- Tablet과 넓은 웹에서는 기존 최대 폭 620의 다이얼로그를 유지하되 키보드가 열린 상태에서도 제출 버튼이 가려지지 않게 한다.
- 처리 중 중복 탭을 막고 성공·실패 후 기존 Provider 갱신 동작을 유지한다.

## 구현 경계

- compact 진입 카드와 전용 화면을 새 위젯으로 분리하고, 데이터 조회와 마감 실행 로직은 한 소유 지점에서 공유한다.
- 기존 private `_DailyClosingSectionState`에 묶인 action 로직은 동작을 바꾸지 않는 범위에서 재사용 가능한 controller/callback 경계로만 추출한다.
- 전용 화면은 `storeId`를 명시적으로 전달한다. 전역 라우터, 역할별 route permission, Supabase 스키마는 변경하지 않는다.
- 기존 desktop 인라인 표를 새 카드 UI로 교체하지 않는다.
- 일일 마감 수치, 영업일 계산, 00:00 Asia/Ho_Chi_Minh 기준, RPC payload를 변경하지 않는다.

## 범위 제외

- 일일 마감 데이터 모델, DB migration, RLS, RPC 변경
- 리포트 전체 정보 구조 개편
- 모바일에서 브라우저 새 탭을 강제로 여는 동작
- 데스크톱 일일 마감 표의 컬럼/스타일 재설계
- 기존 마감 기록 수정·삭제 또는 재오픈 기능

## 완료 판정

- 390×844 Phone, 768×1024 Tablet, 1024×768 Tablet에서 리포트 본문에는 진입 카드만 보이고 15열 표가 직접 나타나지 않는다.
- 진입 카드를 누르면 같은 `storeId`의 일일 마감 전용 화면이 열리고 뒤로가기로 원래 리포트 상태에 복귀한다.
- Phone은 1열 기록 카드, Tablet은 줄바꿈 가능한 그룹형 기록 카드로 모든 15개 값을 읽을 수 있다.
- 1440×900 이상의 넓은 웹에서는 현재 인라인 표와 마감 실행 방식이 유지된다.
- 100%/130%/200% 글자 크기, 세로/가로 회전, 긴 금액/담당자명에서 overflow, 잘린 버튼, 글자 단위 금액 줄바꿈이 없다.
- open/closed, loading/error/empty, 마감 생성 성공/실패, 중복 탭 방지가 기존과 동일하게 동작한다.
- 기존 일일 마감 모델·계약 테스트와 전체 저장소 검증이 통과하며 DB 변경은 없다.
