# FLARE Memory

- [R001] Classify unimplemented operational integration flows as Blocked or Decision Needed until implementation and contracts are confirmed; reserve No-Go for unsafe failure, contamination, broken coupling, or a false Full Go claim.
- [R002] Delivery order state machines must never let a newly received or stale event downgrade an actioned or terminal order; route out-of-order events to anomaly and reconciliation evidence instead of mutating state.
- [R003] Pilot or deploy readiness requires command-backed app-flow coverage plus production auth/profile checks that follow the real auth-ID lookup path; skipped auth checks are blocker-risks, and automation must never create, print, or reset pilot passwords.
- [R004] Compute a print-routing batch number once per enqueue event before iterating copy destinations so all delta jobs from that event retain one batch identity.
- [R005] Restricted-search-path definer functions must schema-qualify extension calls and revoke broad execution unless they enforce internal ownership plus the complete entity-brand-store tuple while preserving required compatibility.
- [R006] RPC contract tests must invoke the callable path and transactionally seed every auth and role fixture they depend on, never rely on function-text inspection or ambient data.
- [R007] Production migrations must be replay-safe and preflight every referenced optional object; missing dependencies must block before mutation or be explicitly deferred.
- [R008] Stop on migration-history mismatches or unresolved confirmation warnings and verify the applied chain before continuing.
- [R009] Execute production SQL through the exact approved fail-fast, single-transaction invocation and emit success only on a zero exit; migration tests must execute preflight, invariant, verification, and rollback assertions.
- [R010] Reassignment mutations must atomically preserve append-only ownership and active-period history, including actor, time, source, and destination, and be exercised through executable RPC tests.
- [R011] Migration backups must be immutable across replays, and rollback must exactly restore original rows, pre-existing constraints, and comments while removing migration-generated history.
- [R012] Verification must assert every required backup object and use anti-join negative checks so live rows missing from backup cannot be hidden by inner joins.
- [R013] Rollback evidence must have deterministic counts and fingerprints anchored in owner-only state; authenticate every evidence table before mutation and test deleted and modified evidence.
- [R014] Production deployment must pin approved project and environment targets and reject runtime target overrides.
- [R015] Block production deploys from dirty worktrees or commits outside approved-main ancestry; bootstrap dependencies in a clean tree instead of relying on caches or an existing tool state.
- [R016] Shell wrappers must not predeclare library-owned readonly variables, and wrapper-entrypoint tests must execute the real invocation to prove pinned targeting and fail-fast behavior.
- [R017] Cross-platform shell tests must branch before empty-array expansion, inspect each command exit code, and construct clean, dirty, or missing Git fixtures explicitly rather than depend on shell-version error semantics.
- [R018] Collector preflight must validate every first-write table, permission, and store identity; monitoring-ledger probes remain best-effort observability and must not block an otherwise valid collection.
- [R019] Parse collector configuration strictly, rejecting unknown booleans and misspelled keys, and place failure reporting in unconditional cleanup so setup or browser failures cannot bypass escalation.
- [R020] Persist an explicit scheduled-slot identity and intended local date and time independently of actual execution, including cross-midnight delayed runs.
- [R021] Scheduled collection intervals are non-overlapping HCM windows ending at 10:00, 12:00, 14:00, 16:00, 18:00, 20:00, and 22:30; the final window is 20:00–22:30 and missing-slot health allows at least 90 minutes of scheduler delay.
- [R022] Never accept cross-surface UX or localization completion from resources, markers, counts, or source inspection. Executable tests must cover every approved route, workflow, and overlay state across three viewports and KO/EN/VI at 200% text scale, asserting real localized content, 48dp targets, semantics, focus, and interaction.
- [R023] Production SQL run through temporary CLI credentials must explicitly assume the fixed database role and verify the effective current user before mutation.
- [R024] Owner-only control-plane and rollback-definition tables must explicitly revoke all service-role access before narrower grants, and tests must reproduce broad default ACLs.
- [R025] Health and alert-delivery state are independent: acknowledgement may suppress duplicate delivery but never clear persistent unhealth, and every unresolved missing or failed slot must remain included beyond the healthy lookback.
- [R026] Expected-work monitoring must compare every effective policy with its complete materialized expectation set; schema, approved policy configuration, and initial materialization must deploy atomically before verification.
- [R027] Exact-interval zero-sales recovery must use an interval-specific row count or flag, never a daily aggregate count.
- [R028] A release-proof label is evidence only when a successful full validation run matches current approved main; local Worker/Judge results are preflight, and required Linux checks must pass on the exact pushed head.
- [R029] Main-only workflows must reject non-main refs before checkout, and run-triggered proofs must compare the event SHA with trusted live-main metadata before checkout plus repeat the comparison afterward for race detection.
- [R030] Release evidence must persist the provider-confirmed deployment SHA and prove approved-main, validated, and deployed SHAs are identical even after transient source metadata is discarded.
