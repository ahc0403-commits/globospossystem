## 운영 DB에서 수행한 비기록 검사

- **READ ONLY 트랜잭션**에서 각 기존 계정의 인증 문맥을 임시 적용하고 마지막에 ROLLBACK했다. 계정·세션·비밀번호·역할·매장 매핑을 변경하지 않았다.
- 포토 운영 계정 6개와 분식클럽 캐셔 2개는 인증 사용자 연결·활성 상태·기본 매장·접근 가능 매장 1개가 일치한다. 인증 사용자 삭제·차단 상태도 없다.
- 각 계정의 자기 매장 사진 정책은 허용되고 타 매장 정책은 거부된다. 기존 사진 메타데이터 조회도 각 매장에서 성공한다.
- 모든 계정의 사진 INSERT **실행계획만** 검사했다. 과거의 비공개 승인 함수 실행권한 오류는 재현되지 않았다. INSERT를 실행하거나 파일을 만들지 않았다.
- 기존 근태 RPC를 잘못된 검사 전용 타입으로 호출해, 허용 계정은 권한 검사를 지난 뒤 타입 검증에서 종료하는 것을 확인했다. 직원 조회·근태 저장까지 실행하지 않았다.
- 허용 계정의 타 매장 RPC는 기존대로 거부된다.
- **bt_kit, bt_tray, bt_1f, bt_2f는 자기 매장 근태 RPC도 기존대로 거부된다.** 사진 버킷의 기존 정책과 근태 기록 권한은 별개다. 이 계정들에 근태 권한을 추가하지 않았다.

## 격리 DB 저장 검사

운영에서 조회한 두 근태 저장 함수의 원문을 로컬 임시 PostgreSQL에 그대로 설치했다. 의존 테이블은 최소 fixture이며 운영 DB 전체 복제나 운영 HTTP 검사는 아니다. 계정 역할·매장 형태는 운영과 같게 구성하고, 계정 ID와 직원은 모두 로컬 합성 fixture로 만들었다.

포토 6개 운영 계정 형태와 분식클럽 캐셔 2개 형태에서 다음이 모두 통과했다.

- 자기 매장 사진 메타데이터 저장, 타 매장 거부.
- 사진을 포함한 출근·퇴근·동일 일자 다음 근무 출근 저장.
- 직원번호 대소문자·앞뒤 공백 정규화.
- 저장된 매장·직원·기록자·유형·사진 URL·썸네일의 일치.
- 중복 출근·중복 퇴근·출근 전 퇴근 거부.
- 없는 직원번호·누락 사진·타 매장 근태 거부.
- 키친·트레이·층별 역할의 근태 거부.
