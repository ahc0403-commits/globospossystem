# 전체 POS 화면 언어·표시 품질 개선 계획

작성일: 2026-09-15
조사 기준: PR #489의 `5c513b535dd9afe0f3c8e9c3f8bd3a8d6ca307e0`
상태: 소스 구현 및 로컬 회귀 검증 완료. DB 적용·웹 배포·운영 확인 대기.

## 0. 구현 결과

이번 변경은 특정 상세 시트가 아니라 `lib/` 전체와 32개 활성 라우트를 대상으로
공통 계약을 적용했다.

- `AppLanguage`가 `en-US`, `en_US` 같은 지역 코드를 정규화하고, 언어 복원·빠른
  연속 선택·저장 실패가 최종 선택을 되돌리지 않도록 저장 순서를 직렬화했다.
- 앱은 저장 언어 복원이 끝나기 전에 라우트 화면을 노출하지 않으며, 저장 실패는
  선택값을 유지한 채 현재 언어의 오류 메시지로 알린다.
- 메뉴/카테고리 이름은 공통 타입을 통해 `ko=name_ko`, `en=name_en`, `vi=name_vi`로
  선택한다. 다른 언어 필드로 조용히 대체하지 않으며, 부분 누락은 원래 식별자와
  선택 언어의 누락 안내를 함께 표시한다.
- 주문, 테이블, 주방, 계산대, QR, Direct Order, 비상 운영, 프로모션, 보고서,
  영수증 원장, 메뉴 관리, 종이 없는 운영 분석의 조회·모델·표시 경계를 정리했다.
- 재고의 고정/서버 생성 영문 상태와 관리자 감사 로그를 KO/EN/VI 표시값으로
  변환했다. PDF 상태, 발주 건수, 포장 표기, 툴팁과 토스트도 같은 기준을 따른다.
- 32개 라우트의 언어 정책과 베트남어 고정 영수증/고객 화면, 3개 언어 병기
  발주서 같은 출력 예외를 [계약 파일](app_language_surface_contract_20260915.json)에
  등록했다.
- AST 기반 필수 테스트가 직접 `Text`/`SelectableText`/PDF 문구, 주요 UI 인자,
  재고 런타임 원문 노출, 새 라우트의 정책 누락, 메뉴의 가짜 번역값과 우회
  fallback을 검출한다.
- DB 마이그레이션은 BM 이력·원주문·매출 분석·영수증뿐 아니라 종이 없는 운영
  메뉴/카테고리 분석도 정확한 언어 필드로 후처리한다. preflight, 검증, rollback,
  반복 적용과 실제 PostgreSQL 회귀 fixture를 포함한다.

초기 483개 후보 목록은 조사 당시의 lexical baseline이며 현재 판정표가 아니다.
활성 라우트와 고정 언어 정책은 계약 파일이 기준이고, 모든 Dart 화면 파일은
정적 검사 대상이다. 운영 완료 판정은 아래 기준대로 DB와 웹을 함께 배포한 뒤
실제 데이터로 확인해야 한다.

## 1. 목표와 범위

**POS의 모든 활성 화면과 그 하위 상태에서 선택 언어, 표시 문구, 업무 데이터,
입력값, 배치, 출력물이 정해진 규칙에 맞게 동작하도록 개선한다.**

메뉴 언어 매칭은 전체 개선의 한 항목이다. 버튼·제목·상태·오류·폼 검증·
팝업·툴팁·접근성 설명·숫자/날짜·검색/정렬·내보내기를 모두 포함한다.
재고 상세와 관리자 감사 로그의 고정 영문 문구도 이번 전체 개선의 필수 완료 항목이다.

현재 업무 기능은 유지하면서 전체 화면의 언어와 표시 문제, 언어 전환으로 생기는
입력/선택 유실 및 동작 회귀를 해결한다. 기능별 화면을 새로 만들거나 업무 규칙을
임의로 바꾸는 작업을 포함하지 않는다.

라우터, 네비게이션, 역할별 탭 생성, `Navigator.push`, 펼침 상세,
커스텀 팝업 호출, 파일 출력 경로를 따라 실제 활성 화면 목록으로 정리한다.
현재 소스와 배포된 앱의 차이도 확인한다. 도달하지 않는 코드와 폐기된 기능은
근거를 남기고 분류하며, 테스트하지 않은 화면을 임의로 비활성 처리하지 않는다.

### 2.3 화면별 관리 단위

각 화면 ID에는 다음 정보를 연결한다.

`진입 경로 → 역할/매장 조건 → 하위 탭/섹션 → 팝업 → 표시 상태 → 데이터 출처 → 언어 기준 → 테스트 → 배포 후 증거`

검증표에는 다음 열이 필요하다.

- 고유 ID, 소스/진입 동작, 활성 여부와 근거.
- 직원/고객/출력물의 언어 기준, 지원 플랫폼과 역할.
- 인터페이스 문구, 데이터 매칭, 상태/오류, 날짜/숫자, 배치/접근성의 판정.
- 언어 전환 중 입력/선택 유지, 캐시/실시간/오프라인 판정.
- KO/EN/VI별 행동 테스트와 필요한 시각 검토 결과.
- 발견 결함, 수정 커밋, 남은 검증, 운영 확인 결과.

하위 상세가 미검증이면 상위 화면도 전체 통과로 표시하지 않는다.

## 3. 전체 앱에 적용할 여섯 가지 공통 규칙

### A. 인터페이스 문구

- 제목, 버튼, 메뉴, 상태, 안내, 오류, 검증, 확인창, 툴팁, 접근성 문구를 ARB 기반으로 통합한다.
- 재고·감사·보고·발주 화면의 고정 영문과 화면별 `pick`/`_text` 등
  자체 번역 사전도 대상으로 삼는다. 정상 동작하는 번역은 보존하면서 사용 경로를 정리한다.
- 단수/복수, 개수, 동적 인자, 용어와 문장 품질을 세 언어에서 확인한다.
- 서버 상태/오류 코드와 화면 문구를 분리한다. 원시 SQL/오류 문자열이
  화면에 노출되지 않도록 명확한 코드와 현재 언어의 안내로 대응한다.
- 나중에 표시할 알림·오류 상태에는 코드와 인자를 보관해 언어 변경 후에도
  과거에 만들어진 문장이 남지 않도록 한다.
- 감사 로그는 동작명·항목명·상태를 번역하고, 실제 변경값과 사용자 원문은 보존한다.

### B. 업무 데이터

- 이미 다국어로 등록되는 메뉴·카테고리·옵션은 선택 언어 필드에 정확히 연결한다.
- 모델·API·캐시·실시간 패치·이력·콤보에서 세 언어 값을 보존한다.
- 상태 코드, 단위 표시, 역할명, 결제 방법, 이벤트 종류 등 시스템 분류값도
  현재 언어에 맞는 표시 이름을 사용한다. API에 보내는 코드 자체는 바꾸지 않는다.
- 매장/사람/법인/공급업체의 고유 이름, 메모, 주소 등 사용자 입력은 데이터
  성격을 판별해 그대로 보존한다. 임의로 번역하거나 언어 오류로 오인하지 않는다.
- 현재 등록값, 당시 스냅샷, 과거 자료의 누락은 구분한다. 누락을 다른 언어로
  조용히 덮어써서 정상으로 판정하지 않는다.
- 검색은 화면에 보이는 번역 이름으로 찾을 수 있어야 하며, 필터·선택·정렬·
  페이지 이동은 안정적인 ID를 사용한다.

### C. 언어 상태와 비동기 동작

- 직원 화면, 독립 고객 화면, 출력물 각각의 언어 선택 기준을 명시한다.
- 저장 언어 복원, 지역 코드 정규화, 기본값, 저장 실패, 빠른 변경을 통일된 규칙으로 처리한다.
- 열린 팝업·드롭다운·상세·검색 결과·알림까지 최신 언어를 반영한다.
- 언어 전환으로 폼 입력, 장바구니, 선택한 매장/기간/탭, 스크롤 위치와
  진행 중 작업을 잃지 않도록 한다.
- 늦은 요청·실시간 갱신·오프라인 캐시가 이전 언어 또는 다른 매장 데이터를
  다시 표시하지 않도록 한다. 결제/발주 제출이 중복 실행되지 않아야 한다.
- 고객 언어와 직원 언어가 서로 덮어쓰이지 않도록 별도로 검증한다.

### D. 날짜·숫자·입력·출력

- 날짜, 시간, 금액, 수량, 퍼센트, 단위의 표시 정책을 공통화한다.
- UI 표시 언어 변경이 실제 금액·수량·세율·영업일·매장 시간대를 바꾸지 않아야 한다.
- 숫자 입력 중 언어 전환과 붙여넣기를 시험한다. 소수점/천 단위 구분의
  모호한 해석으로 값이 변하면 검증 실패로 처리한다.
- Excel/PDF/영수증의 제목·열 이름·상태·메뉴명·오류를 출력 언어 정책에 맞춘다.
  기존에 영문 헤더를 유지한 파일도 이번 검토 범위에 포함한다.
- 기계가 읽는 CSV/Excel 키·법정 양식·가져오기 스키마는 사람이 읽는
  표시 내용과 구분한다. 내보내기 변경 후 재업로드 왕복 검증을 수행한다.
- 출력 시작 시 언어를 확정해 한 파일 내부에서 언어가 섞이지 않게 한다.

### E. 배치와 접근성

- 세 언어 각각에서 긴 문구, 여러 줄, 베트남어 발음기호, 큰 숫자와 긴 데이터로 검증한다.
- 모바일·태블릿·데스크톱과 기본/200% 글자 크기에서 잘림·겹침·버튼 이탈을 수정한다.
- 스크롤이 필요한 표는 의도적으로 스크롤되게 하고 주요 동작을 접근 가능하게 유지한다.
- 핵심 정보는 말줄임만으로 숨기지 않는다. 필요한 곳에 상세/전체 이름 확인 경로를 둔다.
- 터치 영역, 키보드 포커스, 스크린리더 이름, 오류 위치 안내를 함께 검증한다.
- 공통 컴포넌트와 개별 화면을 모두 확인한다. 공통 수정 하나가 다른 화면을 깨뜨리면 통과하지 않는다.

### F. 예외·외부 화면

- 현재 존재하는 베트남어 고정값은 자동으로 정상 예외로 인정하지 않는다.
  고객 디스플레이·주방 짧은 이름·영수증별 운영 정책과 일치하는지 확인한다.
- 필요한 고정 언어/다국어 병기 출력에는 정책과 행동 테스트를 연결한다.
- OS 파일 선택기와 MISA 등 외부 서비스 화면은 앱이 통제하는 문구/언어 전달과
  외부가 통제하는 부분을 구분해 기록한다. 외부 화면을 번역했다고 주장하지 않는다.
- 알려진 언어 정책에 따른 고유명/원문 표시는 결함이 아니다.
  고정 문구를 예외 목록에 넣어 미해결 결함을 숨기지는 않는다.

## 4. 실행 단계

| 단계 | 작업 | 통과 조건 |
| --- | --- | --- |
| 1. 전체 범위 확정 | 초기 목록의 도달 가능성 확인, 역할별 탭·팝업·출력물 추가, 화면별 검증표 작성 | 분류되지 않은 화면/진입점 0건 |
| 2. 전수 결함 수집 | 모든 화면의 문구·데이터·상태·배치·출력 검사, CRITICAL/HIGH/MEDIUM/LOW로 분류 | 각 발견 결함에 재현 경로·언어·데이터·기대 결과 기록 |
| 3. 공통 구조 정리 | 언어 상태, ARB 문구, 데이터 변환기, 상태/오류 표시, 포맷/출력 규칙, 공통 컴포넌트 | 정상 사례와 오류 주입 시험 통과 |
| 4. 전체 화면 수정 | 업무 영역별로 목록→상세→팝업→오류→출력을 한 묶음으로 완료 | 영역 안에 미처리 하위 상태 없음 |
| 5. 전체 회귀 검증 | 모든 화면의 세 언어/화면 크기, 데이터 포함 행동, 비동기/권한/업무 동작 검증 | 해당되는 필수 검증 통과, skip으로 대체한 항목 없음 |
| 6. 재발 차단 | 새 화면/문구/데이터 경로 탐지, ARB/API 계약, 타입/정적 검사, 필수 CI 연결 | 의도적으로 재현한 오류가 모두 필수 체크 실패로 검출 |
| 7. 배포와 운영 확인 | 최종 커밋 체크, DB/앱 호환성, 배포, 실제 화면 대조 | 소스·DB·웹/해당 플랫폼·운영 검증 증거 확보 |

공통 구조부터 정리하되, 구현 순서는 업무 위험도에 따라
주문/주방/계산대 → 관리/보고/마감 → 재고/구매/인력/QC → Photo/고객/출력으로 진행한다.
우선순위가 낮다는 이유로 어느 영역도 전체 완료 범위에서 제외하지 않는다.
독립적인 수정은 검토 가능한 변경으로 나누고, 각 변경이 전체 진행표에 연결되게 한다.

## 5. 테스트의 기준과 구성

### 5.1 모든 화면의 공통 상태

각 화면과 하위 상태에 적용 가능한 아래 사례를 실행한다.

- 최초 진입, 저장 언어 복원, 로딩, 데이터 있음, 데이터 없음.
- 입력/편집, 검증 오류, 저장/제출 중, 성공, 서버/네트워크 실패, 재시도.
- 조회 권한 없음, 일부 동작 권한 없음, 로그인 만료, 매장 변경.
- 펼침 상세, 열린 팝업/시트/선택기, 필터/정렬, 다음 페이지, 내보내기.
- 오프라인 캐시, 재연결, 실시간 변경, 응답 순서 역전, 연속 언어 변경.

상태가 없는 화면은 근거를 기록한다. 핵심 상태를 빈 fixture나 미실행 처리로 넘기지 않는다.

### 5.2 언어·역할·화면 크기

- KO/EN/VI 각각의 초기 표시와 서로 다른 언어 간 6개 방향의 전환.
- 모든 활성 화면/하위 상태 × 3개 언어 × 모바일/태블릿/데스크톱.
- 기본 및 200% 글자 크기. 입력 중에는 모바일 키보드와 안전 영역도 확인.
- 역할에 따라 다른 UI가 있는 경우 각각 검증하고, 같은 UI는 동일 동작이라는 근거를 남긴다.
- 실제 지원하는 웹 브라우저와 Android 키오스크/Windows 프린트 경로를 포함한다.
  사용자 사례의 iPhone 웹에서도 핵심 경로와 팝업을 직접 검증한다.

### 5.3 값과 동작에 근거한 검사

- UI 문구: 현재 언어의 기대 문구, 인자, 상태, 오류 안내와 일치.
- 다국어 데이터: 선택 언어에 해당하는 등록 필드와 실제 표시값이 일치.
- 사용자 원문: 언어 전환 후에도 값이 보존됨.
- 숫자/시간: 표시를 다시 해석해도 값·영업일·시간대 계약이 유지됨.
- 행동: 같은 버튼이 같은 API/업무 동작을 한 번만 수행함.
- 출력: 생성된 실제 파일의 문구·데이터·스키마·합계 확인.
- 시각/접근성: 실데이터 길이의 렌더링과 이미지 검토, 터치·포커스·읽기 순서 확인.

“한글이 없다”, “화면 제목이 번역됐다”, “총 테스트 수가 많다”만으로 통과시키지 않는다.
앞서 통과한 18개 대표 경로·5개 팝업·메뉴 전환 테스트는 기존 기반 증거이며,
전체 화면의 상세·오류·출력 검증을 대신하지 않는다.

### 5.4 재발 방지 시험

다음 결함을 의도적으로 넣어 필수 테스트가 실패하는지 확인한다.

1. 새 화면에 ARB를 거치지 않은 고정 문구 추가.
2. EN/VI 리소스 키·동적 인자·상태/오류 매핑 누락.
3. 메뉴 언어 필드 누락·교환·원본명 직접 표시.
4. 재고/감사 상세의 내부 분류 코드 또는 영문 원시 오류 노출.
5. 열린 팝업/상태 메시지가 이전 언어를 유지.
6. 실시간 변경/캐시 복원으로 데이터나 최신 언어 선택 유실.
7. 긴 번역 문구로 버튼이 가려지거나 조작 불가능해짐.
8. 언어 전환으로 숫자 입력값·필터·장바구니가 바뀌거나 요청 중복 실행.
9. 화면과 PDF/Excel/영수증의 언어·값 불일치.
10. 새 경로·탭·팝업이 전체 검증 목록에서 빠짐.

소스 문자열 검색은 후보 탐지용으로 사용한다. 타입/구문 기반 검사와
실제 동작 테스트를 결합하고, 파일 해시 갱신을 동작 검증으로 취급하지 않는다.

## 6. 진행 보고와 최종 완료 기준

진행률은 다음을 구분해 보고한다.

`전체 활성 화면/상태 수 · 조사 완료 · 결함 발견 · 수정 완료 · 검증 완료 · 운영 확인 완료`

조사나 수정만 끝난 항목에 통과 표시를 하지 않는다. 메뉴만 고쳐진 상태에서
전체 개선을 완료로 보고하지 않는다. 다음 조건을 모두 만족해야 전체 완료다.

- [ ] 활성 화면·하위 탭·상세·팝업·출력물의 목록과 언어 정책이 확정됨.
- [ ] 모든 화면의 인터페이스 문구와 데이터 표시 규칙이 세 언어에서 검증됨.
- [ ] 재고 상세·감사 로그를 포함한 알려진 고정 문구 누락이 해결됨.
- [ ] 정상·로딩·빈 상태·오류·권한·입력·성공의 해당 상태가 검증됨.
- [ ] 언어 전환·초기 복원·캐시·실시간·오프라인에서 불일치와 입력 유실 없음.
- [ ] 모든 해당 화면 크기에서 조작을 막는 잘림·겹침·접근성 결함 없음.
- [ ] 출력물 언어·표시값·재업로드 계약 검증 완료.
- [ ] 알려진 미해결 결함 0건, 미분류 화면 0건, 필수 검증 skip 0건.
- [ ] 주문·결제·주방·수량·금액·권한·매장 범위의 기존 계약에 회귀 없음.
- [ ] 지정한 오류 주입 시험이 모두 결함을 검출함.
- [ ] 정확한 최종 커밋의 필수 GitHub 체크와 해당 플랫폼 빌드 통과.
- [ ] DB 적용·앱 배포·캐시 버전·운영 화면 확인 결과가 각각 기록됨.

운영 기록은 읽기 전용으로 검증하고, 쓰기가 필요한 흐름은 격리 환경에서
검증한다. 실제 장치·외부 연동 등 남은 검증이 있으면 해당 항목을 명시하며
전체 완료로 선언하지 않는다. 배포는 `scripts/deploy_pos_production.sh`의
현재 게이트를 따른다.
