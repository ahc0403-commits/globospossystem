# POS 매출신고 XLSX v3 수신 계약

파일 계약: `pos-sales-xlsx-v3`. 원장 연결 계약: `POS Ledger` 버전 2. 스냅샷 버전과 매핑 버전은 별도 값이다. 외부 MISA 검사·가져오기·발행·전송 시험은 포함하지 않는다. 자동화 소스는 변경하지 않았다.

## 입력 시트

`Hóa đơn GTGT`는 A:Q 17열, 8행 헤더, 9행 첫 데이터다. 안내문 6행과 7행 공란을 유지한다. 병합·수식·추가 입력 열이 없다. XLSX dimension에는 실제 마지막 셀을 기록하므로 읽기 전용 XLSX 파서도 전체 행을 읽을 수 있다.

| 열 | 첫 품목 | 다음 품목 |
|---|---|---|
| A | 양의 정수 텍스트 순번 | 같은 텍스트 순번 |
| B:J | 영업일·고객·원본 결제 구성 | 값 없는 실제 빈 셀 |
| K:L | 승인 명칭·단위 | 각 품목 승인값 |
| M:Q | 수량·출력 단가·공급가액·세율·VAT 숫자 | 해당 품목 숫자 |

소비자는 A를 정규화한 양의 정수로 묶고, 연속 행 B:J를 해당 영수증 첫 행에서 상속한다. 원본 파일의 공란을 다시 채워 쓰지 않는다. 처음 나온 순번에 날짜·결제 정보가 없거나 종료된 순번이 재등장하면 실패해야 한다. 동일 고객·금액·날짜라는 이유로 영수증을 합치지 않는다.

금액은 원본 공급가액과 VAT를 보존한다. 17열에는 할인 열이 없으므로 출력 단가는 원본 공급가액/수량으로 정규화한다. 원래 `unit_price`, `misa_unit_price`, `misa_discount_amount`는 명세에 보존하며 `quantity × misa_unit_price − misa_discount_amount = 공급가액`을 먼저 검증한다. 할인 근거를 숫자 0으로 임의 보정하지 않는다. Photo의 기존 8% 서비스 분할 계산과 Moers → POS 6열 입력 형식은 유지한다.

## 식별자와 승인 명세

기존 `POS Ledger` 14열 순서·의미를 유지한다. 영수증 키는 `(tax_entity_id, source_system, receipt_id)`다. 입력 A와 Ledger의 정수 순번을 정규화해서 비교하고 실제 `excel_row`로 연결한다. 순번은 파일 내부의 번호이며 계산서 발행 번호가 아니다.

`Invoice Mapping`은 품목별 원품목 ID, 실제 승인 ID, 승인 유형, 매핑 버전, 적용기간, 매장, 출처, 원본 단가와 할인 근거를 보존한다. 콤보 세율 행의 `order_item_id`와 공통 `source_order_item_id`를 구분한다. 물티슈는 `item_type` 승인이고 메뉴 ID는 공란이다. Photo는 `source_contract`이며 DB 승인 UUID를 만들어 넣지 않는다.

`Export Contract`는 파일 형식·원장 버전, 생성 UUID, 입력 내용 SHA-256, 영수증 수, 원품목 수, 출력 행 수, 원장 금액·품목별 반올림 예상액·차이를 기록한다. 파일 자신의 해시는 파일 안에 넣을 수 없으므로 POS 화면의 별도 명세 다운로드로 `*.manifest.json`을 제공한다. JSON의 `generation_id`는 파일과 같고 `file_sha256`은 최종 XLSX 바이트의 SHA-256이다. 명세에 고객 연락처를 넣지 않는다.

## 오류와 보호

파일 저장 전 전체 영수증을 검사한다. 수량·금액 누락, NaN/Infinity, 승인 유형·매장·기간 불일치, 중복 영수증/품목, 금액·VAT 오류를 기본값으로 보정하지 않는다. 유효한 영수증만 제외한 부분 파일도 만들지 않는다. POS는 영수증 ID/번호, 품목 ID·명칭, 필드/코드, 판매시각, 매핑 버전, 해결 경로를 100개씩 표시한다.

원장 요약과 페이지에 동일한 `source_revision` 및 `mapping_revision`이 있어야 한다. 기간·법인·소스·페이지 정렬·개수·금액·품목 수가 달라지면 `SALES_REPORT_CHANGED_REFRESH_REQUIRED`로 중단한다. 진행 중 동일 조회만 세션별 공유하고 완료된 조회를 캐시하지 않는다.

수동 외부 신고 완료 기록은 원본 보고 출처·해시와 `user_provided_report` 확인 상태로 보존한다. 2026-10-11 AKJ 식당 105건/Photo 464건은 재처리에서 보호한다. MISA 번호·성공 상태를 추측해 등록하지 않는다. 미발행 재검증은 선택 일자·법인·영수증 100개 이하에서만 원본을 재조립하며, 발행·시도·claim·외부 완료 자료는 보호한다.

## 초기 승인 파일

`invoice_mapping_initial_20261011.json`: 메뉴 73개, 물티슈 유형 1개, Photo 소스 기준 1개. DB 승인 대상은 74개이며 Photo는 독립 계약이다. 원문 명칭·판매분 단위와 `2026-10-11T00:00:00+07:00` 이상 / `2026-10-12T00:00:00+07:00` 미만을 유지한다. 날짜를 자동 확장하지 않는다.

메뉴 ID와 물티슈 대상 매장을 한 번에 해결한 뒤 매장·법인별 100개 이하 배치를 순차 승인한다. 서버가 반환한 실제 프로필 ID를 사용한다. 동일 입력 재실행은 같은 ID를 반환한다. 유효기간 충돌은 전체 배치를 취소한다. 유한한 과거 매핑으로 기존 열린 승인 기간을 자동으로 축소하지 않는다.
