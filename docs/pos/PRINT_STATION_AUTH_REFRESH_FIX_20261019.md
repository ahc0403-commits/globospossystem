# 프린트 스테이션 화면 갱신·독립 로그인 개선

## 변경 범위

- 프린터 목록은 printer_destinations / physical_printers / printer_endpoints 변경과 재연결 복구 때만 갱신한다. 주문·출력 작업 변경은 작업 목록을 갱신한다.
- 목록 notifier를 유지하고, 백그라운드 조회 중 기존 목록·설정 입력·포커스를 보존한다. 같은 범위의 진행 중 요청은 공유한다.
- 기존 로그인 상태에서 프로필 조회가 일시적으로 실패해도 사용자·역할·매장을 비우지 않는다. 계정 비활성, 실제 권한 회수·프로필 삭제·세션 종료는 계속 반영한다. 모든 명시적 로그아웃 범위는 local이다.
- 캐셔, 프린트 스테이션, 고객 화면의 세션 저장소·PKCE 저장소·웹 인증 방송 채널을 분리한다. 인증 공간 이름은 권한을 부여하지 않으며 실제 계정 권한과 서버 RLS를 그대로 사용한다.

## Windows 사용

ZIP 전체를 새 폴더에 풀고 기존 앱을 종료한 뒤 다음 파일을 실행한다. 실행 파일·DLL·data 폴더를 함께 보관한다.

| 실행 파일 | 독립 로그인 공간 |
| --- | --- |
| Start Cashier.cmd | 캐셔 |
| Start Print Station.cmd | 프린트 스테이션 |
| Start Customer Display.cmd | 고객 화면 |

각 실행 파일의 바탕화면 바로가기를 만들 수 있다. EXE 직접 실행의 기본 공간은 프린트 스테이션이다. Windows 창 제목과 로그인 제목도 구분된다. 같은 역할의 바로가기를 여러 번 열면 같은 로그인 공간이므로, 세 화면에는 각각의 실행 파일을 사용한다.

기존 공용 저장소의 세션은 새 저장소로 복사하지 않는다. 업데이트 후 각 공간에서 한 번씩 로그인해야 한다. 기존 서버 세션을 일괄 폐기하는 작업은 수행하지 않는다.

Windows 인증은 앱 지원 폴더의 terminal_auth_v2 아래 역할별 파일에 저장한다. 다른 프로세스의 SharedPreferences 전체 파일 캐시가 세션을 덮어쓰지 않는다. 같은 PC의 프린터 모드 선택 설정은 기존대로 유지한다.

## Chrome·설치 웹 앱

새 웹 버전의 로그인 화면에서 캐셔 / 프린트 스테이션 / 고객 화면을 선택한 뒤 각각 로그인한다. 이름이 지정된 공간은 창을 닫았다 열어도 역할별 저장소에서 복구한다.

- `/?terminal=cashier#/login`
- `/?terminal=print_station#/login`
- `/?terminal=customer_display#/login`

각 링크에서 설치하면 서로 다른 manifest ID·시작 주소의 앱이 생성된다. 같은 역할의 여러 창은 그 역할의 인증 공간을 공유한다. 역할을 선택하지 않은 일반 브라우저 창은 sessionStorage를 사용하며 새 역할 저장소와 인증 알림을 공유하지 않는다. 일반 창은 새로고침 시 로그인 정보를 유지하지만 창을 닫은 뒤의 복구는 보장하지 않는다. 지속 사용에는 위 역할별 링크·설치 앱을 사용한다.

웹 변경은 Windows ZIP 설치만으로 운영 웹에 반영되지 않는다. 웹 소스와 manifest를 함께 배포해야 한다. 이 작업은 소스 개선·검증·빌드이며 운영 웹·DB 배포나 PR 병합은 포함하지 않는다.

## SDK의 최소 변경

고정된 gotrue 2.19.0 원본을 MIT 라이선스와 함께 packages/gotrue에 포함했다. 원본 대비 두 변경만 적용한다: GotrueAsyncStorage의 선택적 authBroadcastChannelKey getter, 그리고 방송 채널 생성 시 해당 값 사용. SDK의 기본 동작, 토큰 갱신, JWT 처리, 서버 API는 바꾸지 않는다. 메모리 세션·영속 세션·PKCE·방송 채널을 같은 공간으로 묶는다. 패키지 업그레이드 시 packages/gotrue/README.md 절차를 따른다.

## 검증 및 조회량

- 실제 Chrome SDK로 서로 다른 3개 인증 공간을 만들고 캐셔 로그아웃·토큰 갱신·이전 공용 SDK의 로그아웃 방송이 다른 두 공간의 사용자·저장 세션을 바꾸지 않는지 확인한다.
- 네이티브 파일 저장소의 세 공간을 새 객체로 다시 읽고, 한 공간 삭제·갱신·연속 저장/삭제가 다른 공간에 영향을 주지 않는지 확인한다. 실제 Windows 동작은 정확한 커밋의 Windows CI에서도 검사한다.
- 실제 PrintStationScreen과 실제 notifier에 주문/출력 이벤트·fallback·프린터 변경·병합 이벤트·일시적 실패를 주입한다. 출력/주문 이벤트 2개는 추가 프린터 설정 조회 0회, notifier 재생성 0회다. 복구/프린터 변경은 기존 목록을 유지하며 동시 요청을 합친다.
- 설정 재조회는 같은 매장·계정당 진행 중 요청 한 쌍(매장 1회, 사용자 1회)을 공유한다. 위젯 검사에서 미저장 입력과 포커스를 보존한다. 신규 항목별 DB/API 조회는 추가하지 않는다.

주요 검사:

```sh
dart analyze --fatal-infos
flutter test
flutter test --platform chrome test/terminal_auth_browser_test.dart
```

실제 매장 PC의 새 ZIP 실행과 물리적 출력 검증은 별도다. 페이퍼리스 자동 출력에 필요한 기존 receipt-only 서버 RPC가 미반영이면 안전하게 시작을 차단하는 동작을 유지한다.
