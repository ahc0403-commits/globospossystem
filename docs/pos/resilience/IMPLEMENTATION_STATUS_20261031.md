# 통합 개선 구현 기록 — 2026-10-31

이 릴리스는 야간 거래 경로 안정화와 최초 개설/공통 의존성 결함을 수정한다.
통합 계획 전체의 운영 인수 완료와 이 릴리스의 구현/검증 결과는 구분한다.

## 구현

- U02/U05: 원래 할인 배정 함수는 그대로 유지하고, 주문 항목의 행별 할인
  재계산을 SQL statement의 변경 주문 집합별 1회로 변경했다. 이전/새 주문
  양쪽을 처리하고 관련 값이 바뀌지 않은 UPDATE는 재계산하지 않는다.
- U04: 할인 잔량 이벤트는 같은 매장/트랜잭션마다 1회 발행한다. 기존
  menu/source_table 계약을 보존하여 이전 웹도 최종 잔량을 다시 읽는다.
  메뉴 ID별 부분 갱신은 아직 구현하지 않았다.
- U03: 단일/합산/분할/비매출 처리의 서버 확정 결과를 목록 재조회와 분리했다.
  전액 정산된 주문은 즉시 대기 목록에서 제거한다. 다른 매장으로 전환한 뒤
  돌아온 성공 응답이 현재 화면을 덮지 않게 한다. 네트워크 오류 시 자동 결제
  재시도는 추가하지 않았다. 전체 도메인의 typed outcome 전환은 남아 있다.
- U04: KDS 읽기 대기열 상한 8, 대기 만료 15초, 재시도를 포함한 물리 HTTP
  deadline 15초를 적용했다. 공유 Auth client를 닫지 않는다. 놓친 변경 확인은
  기존 주기로 유지하고 설정 전체 확인은 30초마다 수행한다.
- U04/U10: health 확인을 Future timeout에서 실제 abort/전용 client 종료로 바꿨다.
- U07: 매장 없는 최고관리자도 계층 관리에 접근한다. 이전 onboarding URL은
  현행 관리 경로로 이동한다. 법인 등록 UI는 기존 인증 RPC와 재시도 시 유지되는
  UUID를 사용한다. Office의 첫 법인 소유 관계 연결까지 완결한 것은 아니다.
- U08: QC template 조회에 매장 변경 시 초기화, 응답 세대, disposal 보호를 추가했다.
- U09: lib의 main.dart 역참조 103개를 제거했다. client 접근과 테마 의존을 하위
  모듈로 옮겼고, 기존 main export는 테스트/외부 진입점 호환을 위해 보존했다.
- U11: 확정 후 조회 지연, QC 응답 역전/disposal, KDS 대기열 초과, bootstrap
  역참조 방지 테스트를 추가했다. 기존 할인 SQL 스크립트에서 새 migration과
  SQL statement 배치/이벤트 횟수 검증을 함께 실행한다.
- U12: 하나의 공식 DB/web release-plan과 원래 할인 배정 함수 보존 검사를 추가했다.

## 개발 검증

- Flutter 영향 검사 30개 통과: 새 회귀 검사, 결제 할인 경계 복구, KDS wire/catch-up,
  전가복 bounded sync/동시 읽기/오류 복구.
- 관리자/온보딩/운영 화면 영향 검사 21개 통과.
- Dart 분석 오류/경고 없음.
- PostgreSQL 17 격리 SQL 검사 통과. 100개 INSERT/UPDATE/DELETE가 각각 주문
  1개의 할인 재계산 1회를 실행하고, 무관한 UPDATE는 0회 실행함을 확인했다.
  동일 트랜잭션의 같은 매장 잔량 변경은 기존 형식 이벤트 1회로 확인했다.
- 기존 마지막 수량 동시 주문, 취소/복구, 정상가, 옵션/분할, 후불 snapshot,
  원래 결제 함수 보존 검증도 통과했다.
- 위 결과는 개발 영향 검증이며 최종 SHA의 공식 전체 검증/운영 반영 PASS가 아니다.

## 남은 통합 계획 범위

U01의 최초 야간 병목 확정과 시계열 운영 추적, 모든 RPC 최종 구성의 자동 대조,
전체 도메인 typed outcome/unknown 복구, 선택 주문 상세/메뉴 ID별 부분 갱신,
백그라운드 전체 작업의 통합 예산, Office의 새 법인 첫 소유 관계 등록,
모든 provider의 scope 계약 전환, 대형 화면 책임 분할, 8–12시간 실제 단말 측정,
새 법인부터 마감까지 두 DB 전체 E2E와 전체 혼합 부하는 별도 구현/인수 대상이다.
이 항목을 완료 또는 PASS로 표시하지 않는다.

## 운영 적용 기록 위치

공식 deployer가 생성한 최종 SHA의 release archive/receipt/실행 로그를 근거로
DB 이력, 배포 ID/URL/자산 동일성, 영향 기능, 오류율과 미실행 항목을 별도로 보고한다.
기존 운영 로그인 스모크 면제는 NOT_RUN_OWNER_WAIVER로 유지한다.
