# 테이블 메뉴 이동과 QR 누적 결제 금액

2026-10-24 사용자 요청에 따른 구현. 로컬 검증 전환 PR 628이 병합된 main을 기준으로 하며, 기존 사용자 작업 공간의 변경은 포함하지 않는다.

## 동작

- `cashier_move_order_items`의 세 임시 매핑 UPDATE에 선택 행 조건을 추가한다. 운영 안전 갱신 정책을 끄지 않는다. 트랜잭션, 권한, 요청 멱등성, 가격/옵션 스냅샷, FIFO 및 다중 주방 진행 이력은 보존한다.
- QR의 `payment_summary`는 유효한 토큰의 매장/테이블에 속한 현재 고객 미결제 주문 전체를 집계한다. 아직 조리 중인 주문과 서빙 완료 품목도 포함한다. 취소, 무료 품목, 할인 배분, VAT 포함/별도 가격, 세율별 서비스료, 물티슈 및 기결제를 반영한다. 장바구니 미접수 금액은 합치지 않는다.
- 금액은 기존 캐셔와 같은 `calculate_item_vat` 및 서비스료 반올림 기준을 사용한다. 민감한 결제 상세/직원 정보는 응답에 포함하지 않는다. 내부 집계와 기존 하위 reader는 직접 호출 권한을 부여하지 않는다.
- 주문 완료 화면의 추가 주문 버튼 위와 추가 주문 메뉴 상단에 현재 결제 잔액을 표시한다. 부분 결제 시 총액/기결제도 표시한다. 한/베/영, 320px 및 글자 200%를 검사한다.
- 주문 성공 직후 서버 요약을 한 번 갱신한다. 그 이전에 진행 중이던 조회는 새 주문 금액으로 사용하지 않는다. 활성 주문이 있는 전경 화면은 15~18초 간격으로 요약만 조회하고, 수동 새로고침 및 화면 복귀도 지원한다. 메뉴 조회와 요약 조회의 진행 중 요청을 공유한다. 백그라운드/종료 시 타이머를 중단한다.
- 조회 실패는 확인된 마지막 금액과 갱신 필요 상태로 표시한다. 새 주문 직후 금액을 아직 확인하지 못한 경우에는 이전 합계를 재사용하거나 0원으로 추정하지 않는다. 주문 종료/테이블 주문 교체 시 이전 상태를 비운다.

## 데이터 접근

대상은 현재 매장/테이블의 유효한 주문/품목이다. 금액, 할인 및 결제를 각 관계별로 먼저 집계해 JOIN 중복 합산을 피한다. QR 기초 진행 조회, 포장 모드 및 진행 보정의 품목별 OFFSET/반복 테이블 조회를 일괄 CTE로 변경하고 안정적인 order_item_id를 전달한다. 품목 수에 따라 RPC를 추가하지 않는다. 화면당 요약 요청은 한 번에 하나이며 별도 무제한 재시도는 없다.

좁은 결정적 PostgreSQL 17.6 fixture에서 1/50/500개 품목의 응답 크기와 실행 시간을 기록한다. 실제 운영 스키마를 복원한 별도 네트워크 차단 컨테이너에서 전체 트리거/FIFO, QR 기초 응답 및 진행 보정의 기존 결과 동등성을 별도로 검증한다. 좁은 fixture의 수치는 운영 동시 접속 성능 보증이 아니다.

## 검증과 반영

- 필수 로컬 저장소 검사에 `test/cashier_item_edit_sql_test.sh`를 포함한다. 실제 safeupdate 확장으로 수정 전 오류와 원복을 재현하고, 최신 10월 21일 RPC에 수정본을 적용한 이동, 재시도, 합산/결제 잔액 및 동시 결제 충돌을 검사한다.
- `scripts/test_table_move_current_schema.sh <승인된 public,pos_invoice_private schema-only export>`로 현재 스키마에서 추가 업그레이드/동등성 검사를 수행한다. 운영 데이터는 사용하지 않는다.
- Flutter 화면/모델 및 기존 주문 회귀 검증 후 커밋된 후보 SHA에 공식 로컬 게이트 전체를 실행한다. 정상 PR 병합 뒤 깨끗한 최신 exact-main에서 공식 배포 스크립트가 같은 검증을 새로 실행한다.
- 적용 마이그레이션은 `20261024110000_table_move_and_qr_payment_summary.sql` 하나다. 공식 preflight/verify와 migration-history 확인을 유지한다. 로컬 검증 전환은 이미 main에 포함된 도구 변경이므로 별도의 DB 데이터 수정은 없다.
- DB를 먼저 반영하고 웹을 배포한다. 새 응답 필드는 구버전 앱에서 무시된다. 웹을 이전 버전으로 복구해도 DB 수정과 주문 데이터는 보존할 수 있다. 새 함수를 수동 삭제하거나 실패하는 이동 함수로 되돌리지 않고 검증된 후속 마이그레이션으로 수리한다.

운영 적용 및 검증 결과는 별도의 최종 SHA 증거/운영 보고서에 기록한다. 이 문서 자체는 배포 완료 증거가 아니다. 네이티브 Windows 앱 패키지는 이번 웹/DB 배포 산출물에 포함하지 않는다.
