# 매출 추이·첫 로그인 개선 결과

작성일: 2026-09-06. 사용자 요청에 따라 로컬 작업 트리에서 구현했다. 운영 DB 변경이나 배포는 수행하지 않았다.

## 구현

### 선택 기간 이동평균

- 3일·7일 고정 규칙을 제거하고 선택 기간의 달력 일수 N을 사용한다. 7일·14일·30일과 사용자 지정 기간에 동일하게 적용한다.
- 그래프 첫날부터 N일 평균을 계산할 수 있도록 직전 N−1일의 매출만 별도로 조회한다. 선택 기간 합계, 시간대별 집계, 팀 수, Excel에는 추가 과거 데이터를 넣지 않는다.
- 과거 구간은 매출 인정 결제, 완료된 외부 매출, Photo 수기 신고 집계에서 가져온다. 결제 분할의 `amount_portion`과 Photo 서비스 매출 제외 규칙은 기존 집계를 재사용한다.
- 최신 main과 통합하면서 과거 조회도 기존 `get_store_report_summary` 서버 집계 API로 전환했다. 같은 매출 규칙과 단일 스냅샷 집계를 재사용하며 원본 거래의 추가 전송이나 페이지 제한에 의존하지 않는다. 조회 실패·범위 불일치는 성공으로 처리하지 않는다.
- 평균 계산을 누적합 방식으로 변경했다. 기간이 길어져도 각 평균점마다 전체 N일 목록을 다시 더하지 않는다.
- 평균선이 최근 매출보다 높을 때도 Y축 범위 안에 보이게 하고, 점 하나인 경우에도 식별되게 표시한다.
- 날짜 입력 중인 값과 적용한 기간을 구분한다. 이전 기간의 늦은 응답이 새 결과를 덮지 못하도록 요청 순서를 검증한다.
- 베트남 날짜 기준을 적용했다. 오늘 0원 매출을 평균의 마지막 점에서 제외하는 기존 규칙을 보존하고, 오늘 제외·부분 집계 여부를 안내한다.
- 과거 구간 조회가 실패해도 선택 기간 매출은 유지하며 평균선의 이전 기간 조회를 재시도할 수 있다. 조회에 성공한 빈 날짜는 기존 보고서와 같이 달력상 0원으로 계산한다.

주요 파일: `lib/features/admin/widgets/sales_revenue_analysis_dashboard.dart`, `lib/features/admin/report_analysis_screens.dart`, `lib/features/report/report_provider.dart`, `lib/features/report/revenue_history_provider.dart`.

### 첫 로그인 및 상단 선택창

- 관리자 최초 진입에는 선택한 탭만 마운트한다. 다른 탭의 조회는 첫 방문까지 시작하지 않는다. 방문한 탭은 전환 후에도 유지하고 매장·역할 범위가 달라지면 다시 생성한다.
- 로그인과 `signedIn` 이벤트의 동시 프로필 조회를 공유한다. 독립적인 매장 목록·동의 확인은 동시에 시작한다.
- 로그아웃·매장 변경·객체 종료 이후 이전 프로필 응답이 상태를 덮지 못하게 한다. 필수 비밀번호 변경·개인정보 동의·계정 활성 여부 확인은 유지한다.
- 중앙 라우터만 로그인 후 경로를 결정한다. 로그인 화면이 별도로 홈으로 이동해 기존 복귀 경로나 필수 확인을 덮는 처리를 제거했다.
- 로그인 제출 시 입력 포커스를 해제해 키보드 종료가 화면 전환 전에 시작되도록 했다.
- 첫 테이블 조회가 진행 중이면 탭의 초기화 코드가 같은 조회를 다시 시작하지 않는다.
- 상단 선택창은 기존처럼 본문과 별도 영역에서 유지한다. 10초 로딩 지연·본문 실패·키보드 높이·200% 글씨 조건에서 표시와 클릭 가능 여부를 검증한다.
- 큰 글씨에서 공통 로딩 문구가 가로로 넘치는 현상을 재현하고 줄바꿈되도록 수정했다.

주요 파일: `lib/features/admin/admin_screen.dart`, `lib/features/admin/tabs/tables_tab.dart`, `lib/features/auth/auth_provider.dart`, `lib/features/auth/login_screen.dart`, `lib/core/ui/toast/toast_primitives.dart`.

## 전체 검사에서 구분할 기존 작업

작업 시작 전부터 수정되어 있던 `lib/features/cashier/cashier_screen.dart`와 `lib/core/payments/payment_total_calculator.dart`가 파일 해시 고정 검사 기준과 다르다. 사용자의 기존 수정은 보존했다.

- `test/direct_delivery_regression_isolation_test.dart`: 위 두 파일의 해시 불일치. 이번 작업에서 변경한 보고서 파일의 기준 해시만 갱신했다.
- `test/direct_order_arrival_alert_test.dart`: 계산대 파일의 해시 불일치. 이 테스트에 있던 사용자 변경도 보존했다.

이 실패를 숨기기 위해 기존 계산대·결제 파일을 되돌리거나 해당 파일의 검사 기준을 바꾸지 않았다. 임시 worktree의 검증 성공과 별개로, 기존 작업이 함께 있는 현재 폴더의 전체 검사 및 운영 배포 게이트를 통과했다고 보고하지 않는다.

## 남은 운영 확인

- 첨부 증상이 발생한 실제 기기·브라우저에서는 아직 확인하지 못했다. 키보드 포커스·초기 조회 부하를 개선하고 재현 가능한 화면 넘침을 수정했지만, 운영에서의 상단 누락 해결 여부는 배포 후 동일 기기에서 확인해야 한다.
- 실제 네트워크에서 로그인 전후 p95와 50% 단축 목표는 측정하지 않았다. 자동 테스트는 초기 탭 생성 수와 프로필 요청 중복 제거, 지연 중 조작 가능 여부를 확인한다.
- 출시 시 정확한 pushed head SHA의 필수 GitHub Actions 성공과 `scripts/deploy_pos_production.sh` 게이트를 따른다. 현재 상태는 로컬 구현 및 검증이며 운영 배포·운영 확인과 구분한다.
