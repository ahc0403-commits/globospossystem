# 음료 표시 당류별 VAT 설정 및 분식클럽 메뉴 조정 계획

작성일: 2026-09-29 (Asia/Ho_Chi_Minh)

상태: 2026-09-29 소스 구현 및 격리 DB 검증 완료. 운영 DB는 읽기 전용으로 확인했으며 migration 적용과 운영 배포는 미실행이다.
구현·검증·배포 준비 내용은 [구현 기록](beverage_sugar_vat_implementation_20260929.md)을 참조한다.
검토 기준: HEAD `cc4de81a`와 현재 작업 디렉터리의 변경 사항을 포함한 소스.
기존 수정 파일과 사용자 소유 미추적 파일은 그대로 보존한다.

## 1. 목표와 적용 기준

메뉴 추가·수정 시 음료의 표시 당류를 기록하고, 해당 메뉴의 VAT를 8% 또는 10%로 결정한다.
같은 주문 안에서 음식·저당 음료 8%와 고당 음료·주류 10%를 함께 처리한다.
캐셔 예상 금액, 실제 결제, 고객 디스플레이, 영수증, 매출 원장, MISA 전자세금계산서가 일치해야 한다.

법률 기준을 확인한 결과:

- 기준 문구는 `trên 5g/100ml`, 즉 **5g/100ml 초과**이다. 정확히 5.00은 초과에 포함되지 않는다.
- 베트남 재무부는 해당 TCVN 청량음료가 2026-01-01부터 2026-12-31까지 VAT 2% 감면 대상에서 제외된다고 설명한다. 해당 상품의 VAT는 10%로 처리한다.
- 당류 기준은 제품 라벨의 **총당류**다. 탄수화물이나 첨가당만의 수치로 대체하지 않는다.
- 특별소비세(TTĐB)의 2027년 8%·2028년 10% 일정과 판매 시 VAT를 구분한다. 이번 변경은 POS VAT 분류 개선이다.
- 모든 음료에 당류 수치만으로 일괄 적용하지 않는다. TCVN 기준 대상 음료인지 먼저 구분한다.
- 2026년 감면 종료 이후의 VAT는 후속 법령 확인 후 별도 변경한다. 8%를 영구 법정값으로 설명하지 않는다.

## 2. 기존 메뉴 조정 목표

아래는 사용자가 지정한 분식클럽 판매 상품 기준이다. 실제 제품 라벨이나 운영 DB의 현재 세율을 확인했다는 뜻은 아니다.

| 상품 | 등록할 당류 분류 | 목표 VAT |
|---|---|---:|
| 코카콜라 일반 | 5g/100ml 초과 | 10% |
| Sting | 5g/100ml 초과 | 10% |
| 코카콜라 제로 | 5g/100ml 이하 | 8% |
| Fanta | 5g/100ml 이하 | 8% |
| Sprite | 5g/100ml 이하 | 8% |

정확한 g 수치는 제공되지 않았으므로 임의로 입력하지 않는다. 우선 위 분류와 사용자 지정 근거를 기록하고 실제 판매 SKU의 라벨 수치를 나중에 보완할 수 있게 한다.
Fanta·Sprite 등을 브랜드명만으로 전 매장에 일괄 분류하지 않는다. 맛·용량·수입국·제품 개편으로 다른 SKU는 개별 확인한다.

## 4. 권장 설계

### 4.1 최소 데이터 확장

기존 `vat_category`를 보존하면서 아래 정보만 추가하는 방식을 권장한다.
일반 메뉴 분류와 실제 세율을 분리해 음료를 주류로 오분류하지 않는다.

| 필드 제안 | 의미 |
|---|---|
| `beverage_sugar_tax_class` | 대상 아님 / 대상 음료 5g 이하 / 대상 음료 5g 초과 |
| `sugar_g_per_100ml` | 라벨 총당류 수치. 미확인은 NULL, 0과 구분 |
| `tax_basis_note` | 라벨·SKU 또는 당류 구간 확인 근거 |
| `effective_vat_rate` | 공통 SQL 계산 결과로 API에 제공하는 읽기 전용 값 |

필드명은 구현 시 기존 RPC 명명 방식과 맞춘다. 임의 세율 입력이나 범용 세금 엔진은 이번 범위에 추가하지 않는다.

- 수치가 입력되면 서버가 `> 5` / `<= 5`를 결정한다. 분류와 수치가 충돌하면 저장을 거부한다.
- 수치가 아직 없어도 확인한 당류 구간과 근거를 입력하면 저장할 수 있다.
- 대상 음료의 분류가 미확인이면 자동으로 8%를 부여하지 않고 분류 입력을 요구한다.
- 주류와 음료 당류 분류를 동시에 지정할 수 없게 한다.
- 음수, 비정상 숫자, 잘못된 구분값은 DB/RPC에서도 거부한다.
- 관리 권한과 매장 범위를 기존 메뉴 권한으로 검증하고 세금 변경 전후를 기존 감사 경로에 기록한다.
- 레거시 일반 메뉴는 기존 동작을 유지하되 음료 검토 대상을 별도로 추출한다.

### 4.2 관리자 화면

메뉴 추가·수정 화면에 `음료 당류별 VAT` 항목을 둔다.
대상 음료를 선택하면 `표시 총당류 (g/100ml)`와 `5g 이하 / 5g 초과` 분류, 적용 VAT를 표시한다.
수치 미확인 시에는 확인한 구간과 근거를 입력하도록 한다.
안내 문구는 `5g 초과 10%, 5g 이하 8% — 2026년 기준`으로 표시한다.

메뉴 목록에 VAT 배지를 표시해 여러 음료의 설정을 빠르게 확인한다.
저장 후 재진입·재로그인에서도 설정이 유지되어야 한다. 한국어·베트남어·영어 문구를 함께 추가한다.

Excel 신규 등록·수정·전체 교체·내보내기 경로에 동일 필드를 연결한다.
기존 파일에 새 열이 없는 것은 ‘세금 설정 변경 없음’으로 처리한다.
기존 메뉴의 세금 정보가 구버전 Excel 때문에 8%로 초기화되지 않도록 한다.

### 4.3 세율 결정과 주문 보존

- 공통 SQL 세율 결정 함수를 만들고 메뉴 API·주문 생성·직접 주문 견적에서 재사용한다.
- 새 주문 항목에 서버가 결정한 `vat_rate`와 분류 근거를 스냅샷으로 저장한다.
- 프런트엔드는 해당 세율로 미리 계산하고, 서버는 동일 스냅샷으로 결제 금액을 검증한다.
- `vat_rate = 0`인 레거시 데이터와 실제 서비스 제공 항목을 구분한다. 0을 모두 8%로 보정하지 않는다.
- 메뉴 세금 변경은 변경 이후 추가되는 주문 항목부터 적용한다. 기존 항목의 수량 변경은 저장된 세율을 유지한다.
- 이미 부분 결제되거나 완료된 주문, 발행된 영수증·MISA 스냅샷은 메뉴 변경으로 다시 계산하지 않는다.
- 세금 적용 전환은 대상 음료를 포함한 미완료 주문·부분 결제·대기 직접 주문을 정리한 영업 종료 시점에 진행한다.
- 진행 중인 결제 견적과 서버 금액이 달라지면 기존 금액 불일치 처리로 새 금액을 표시하고 재시도한다.

### 4.4 금액 계산과 증빙

- 가격 VAT 별도 매장: 공급가액에 품목별 8% 또는 10%를 더한다.
- 가격 VAT 포함 매장: 판매가격은 유지하고 해당 세율로 공급가액과 VAT를 역산한다.
- 할인은 기존 항목별 배분과 반올림 규칙을 보존하고, 배분 후 금액을 해당 항목 세율로 계산한다.
- 서비스차지 계산은 8%/10% 과세표준별로 분리한다. 고당 음료가 10% 계산 때문에 주류로 표시되지 않게 한다.
- 서비스 제공·직원식·비매출 결제·취소·물티슈 고정요금의 기존 예외를 유지한다.
- POS·QR·포장·직접 주문·분할/합산 결제·고객 디스플레이를 같은 기준으로 검증한다.
- 정산·원장·영수증·MISA는 저장된 품목별 세액을 집계한다. 메뉴의 현재 설정으로 과거 매출을 재구성하지 않는다.
- MISA 전송은 기존 비동기 경로를 유지한다. 전송 실패가 결제 완료를 막지 않게 한다.
- 서로 다른 업무의 기존 정산 Edge Function 두 개는 각각 유지하고 관련 경로만 확인한다.

콤보는 대상 음료의 포함 여부와 선택 음료 경로를 먼저 조사한다.
단품 메뉴 수정만으로 부모 콤보의 VAT가 자동 수정된다고 가정하지 않는다.
서로 다른 세율이 섞인 유상 콤보는 구성품별 공급가액 배분 기준을 정하고 세율별 증빙 항목으로 연결해야 한다.
구성품 정상 판매가 비례 배분을 검토안으로 두되, 실제 판매·회계 처리 기준을 확인한 후 확정한다.
해당 콤보가 판매 중이면 배분·반올림·표시 검증을 이번 릴리스 완료 조건에 포함한다.

## 5. 구현·데이터 조정 순서

1. **현황 확정**: 운영 DB를 읽기 전용으로 확인해 분식클럽 매장 ID, 메뉴 ID, SKU, 기존 분류, 가격 VAT 모드, 미완료 주문, 콤보 사용 여부를 표로 추출한다.
2. **서버와 앱 구현**: 신규 migration, 공통 VAT 결정, 주문 스냅샷, 결제/할인 계산, 관리자 UI, Excel 및 주문 채널을 연결한다.
3. **기존 메뉴 조정 준비**: 목표 5개 상품을 매장 ID + 메뉴 ID로 고정한 변경 전후 목록과 복원 데이터를 만든다.
4. **통합 검증**: 아래 시나리오로 프런트엔드·SQL·증빙의 금액을 대조한다.
5. **배포·전환**: 필수 GitHub Actions 통과 후 공식 배포 스크립트로 적용한다. 대상 진행 주문이 없는 시점에 5개 상품 분류를 활성화하고 POS를 새로고침한다.
6. **운영 확인**: 매장별 세율 재조회, 8%/10% 혼합 결제, 영수증, MISA 전송 결과를 확인한다.

기존 분식클럽 seed에는 매장 ID 두 개가 있으므로 두 매장을 초기 확인 대상으로 삼는다.
현재 매장·활성 SKU 수는 운영 조회로 확정하며, 소스의 과거 건수를 운영 현황으로 간주하지 않는다.
이름 검색은 후보 찾기에만 사용하고 `콜라` 부분 일치로 제로콜라까지 변경하지 않는다.
대상 누락·중복·예상 상태 불일치 시 migration이 실패하도록 조건을 둔다.

스키마·계산 변경과 매장 데이터 조정은 분리해 검증 가능한 단위로 만든다.
앱/DB 배포 중 새 세율을 아직 이해하지 못하는 오래된 클라이언트가 주문하지 않도록 전환 시점에 세션을 갱신한다.

과거 세금 차이가 필요하면 별도 읽기 전용 영향 보고서로 산출한다.
완료 주문과 발행된 전자세금계산서의 소급 수정은 이 데이터 조정에 포함하지 않는다.
과거 증빙 정정은 확인된 업무 절차와 기존 MISA 포털 경로를 따른다.

## 6. 검증 및 완료 조건

| 검증 | 기대 결과 |
|---|---|
| 총당류 0 / 4.99 / 5.00 / 5.01 | 대상 음료 기준 각각 VAT 8 / 8 / 8 / 10% |
| 숫자 미확인 + 구간과 근거 입력 | 구간으로 계산, 허위 숫자 저장 없음 |
| 분류와 숫자 충돌 / 음수 / 미분류 대상 음료 | 서버와 UI에서 검증 오류 |
| 공급가 100,000 VND씩 음식 8% + 콜라 10% | VAT 18,000, 결제 218,000 VND |
| 위 주문에서 메뉴 금액 10% 할인 | 할인 21,800, VAT 16,200, 결제 196,200 VND |
| 할인 없는 위 주문에 서비스차지 5% | 서비스차지 VAT 포함 10,900, 총 결제 228,900 VND |
| VAT 포함가 108,000 음식 + 110,000 콜라 | 공급가 합계 200,000, VAT 18,000, 결제 218,000 VND |
| 신규 메뉴 저장·수정·Excel 왕복 | 당류·분류·세율 유지 |
| 구버전 Excel로 메뉴 수정 | 기존 음료 세금 설정 유지 |
| 메뉴 세금 수정 후 부분 결제/완료 주문 조회·재출력 | 기존 스냅샷과 금액 유지 |
| 콤보에서 콜라 ↔ 제로콜라 선택 | 확정한 배분 기준에 따라 VAT 반영, 총액·증빙 일치 |
| 매장 권한 밖 메뉴 수정 | 거부 |
| MISA 장애·재시도 | 결제는 완료, 재시도에도 같은 증빙 스냅샷 사용 |

검증 산출물:

- 당류 분류·관리자 저장·Excel 호환 Flutter 테스트.
- 기존 `payment_total_calculator_test.dart` 확장 및 SQL과 동일한 금액 fixture 비교.
- SQL 권한, 세율 제약, 주문 스냅샷, 할인/서비스차지, 분할 결제 및 동시성 테스트.
- QR·직접 주문·고객 디스플레이·영수증·MISA 혼합 VAT 통합 검증.
- Dart format/analyze, 관련 테스트, `scripts/check_repo.sh`와 필수 CI 검증.
- 운영용 preflight / verify / rollback SQL 및 변경 전후 대상 메뉴 목록.

배포는 `scripts/deploy_pos_production.sh`를 사용한다.
정확히 배포할 pushed head SHA의 필수 GitHub Actions 성공을 확인하기 전에는 release gate PASS로 보고하지 않는다.
복원 시 신규 세율로 이미 완료된 주문·증빙은 보존하며, 이후 주문에 대한 설정과 코드 복구를 구분한다.
최종 보고에서 ‘소스 구현 / DB 적용 / 운영 배포 / 운영 검증’을 각각 명시한다.
관련 현재 시스템 문서도 실제 구현에 맞춰 갱신한다.

구현 시 확인: BunsikClub Binh Thanh와 SAMPLE의 대상 메뉴는 매장당 5개, 합계 10개이며 현재 모두 food 분류다.
일반 콜라·Sting 4개를 10%, 나머지 6개를 8%로 설정하는 ID 기반 migration을 준비했다.
정확한 당류 수치는 입력하지 않았고 사용자 확인 구간과 근거만 기록한다.
콤보는 주문 당시 구성품의 단품 가격 × 수량 비율로 금액을 배분하도록 구현했다.
