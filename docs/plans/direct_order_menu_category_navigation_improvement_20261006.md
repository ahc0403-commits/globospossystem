## 2. 권장 화면과 선택 동작

**상단에 고정된 가로 카테고리 바를 추가하고, 선택한 카테고리의 메뉴를 표시한다.** 초기 선택은 `전체`다.

배치 예시의 음식 이름은 설명용이며 실제 이름과 순서는 해당 매장 데이터를 사용한다.

```text
매장명                                  언어
메뉴               배송지             주문 현황
─────────────────────────────────────────────
[전체]  [인기 메뉴]  [떡볶이]  [사이드]  [음료] →
─────────────────────────────────────────────
선택한 범위의 메뉴 카드
메뉴 사진 · 이름 · 가격 · 수량 추가/감소
              ↕ 메뉴 목록 스크롤

장바구니 보기 · 총 수량 · 금액       배송지로 이동
```

| 행동 | 결과 |
|---|---|
| 메뉴 화면 최초 진입 | `전체` 선택. 기존처럼 카테고리별 제목과 메뉴를 보여준다. |
| 특정 카테고리 선택 | 해당 카테고리 제목과 메뉴만 표시하고 메뉴 목록을 맨 위로 이동한다. |
| `전체` 재선택 | 모든 표시 가능한 카테고리의 메뉴를 기존 순서로 표시한다. |
| 이미 선택한 카테고리 다시 누름 | 선택과 목록 위치를 유지한다. |
| 메뉴 수량 변경 | 현재 카테고리와 스크롤 위치를 유지한다. |
| 배송지 화면에서 메뉴 화면으로 복귀 | 유효한 카테고리 선택과 장바구니를 유지한다. |
| KO/VI/EN 전환 | 카테고리와 메뉴 이름을 즉시 바꾸고 ID 기반 선택·수량·메모를 유지한다. |
| storefront 재조회에서 선택한 카테고리 소멸 | `전체`로 복귀하고 목록을 맨 위로 이동한다. |

카테고리 클릭은 현재 응답을 이용하는 로컬 동작이다. 카테고리마다 서버를 다시 호출하지 않는다. 기존 메뉴/배송지 진입 시 접수 가능 여부를 재확인하는 동작은 유지한다.

## 3. 표시·접근성·데이터 규칙

1. **항상 접근 가능한 위치:** 기존 진행 탭 바로 아래에 카테고리 바를 둔다. 바는 세로 메뉴 목록 밖에 배치해 메뉴를 내려도 화면 상단에 남는다. 메뉴 화면에서만 표시한다.
2. **많은 카테고리:** 한 줄 가로 스크롤을 사용한다. 모바일에서 가로 스와이프할 수 있고, 데스크톱에서는 넘치는 경우 방향 버튼으로 이동할 수 있게 한다. 선택 또는 언어 변경 후 선택한 칩이 보이도록 가로 위치를 보정한다.
3. **긴 이름:** 여러 줄 카테고리 바를 만들지 않는다. 칩 폭의 상한과 말줄임을 적용하고 접근성 이름·툴팁에는 전체 이름을 제공한다. 큰 글씨에서도 세로 잘림이 없도록 높이를 조정한다.
4. **선택 상태:** 기존 테마의 색·테두리와 선택 표시를 사용하고 `Semantics`에 버튼·선택 상태를 제공한다. 최소 48 논리 픽셀의 터치 영역과 키보드 포커스를 보장한다.
5. **순서와 번역:** 서버가 반환한 관리자 카테고리 순서를 사용한다. 이름으로 재정렬하거나 음식 카테고리를 하드코딩하지 않는다. `전체`와 빈 상태 문구는 `DirectOrderCopy`에 KO/VI/EN으로 추가한다.
6. **표시 범위:** `storefront.categories`와 해당 카테고리에 속한 `storefront.items`의 교집합을 공통 표시 목록으로 사용한다. `전체` 선택 시에도 이 목록만 보여준다. 카테고리가 누락되거나 비활성인 메뉴가 새로 노출되지 않게 한다.
7. **빈 데이터:** 응답에 카테고리만 있고 대응 메뉴가 없으면 그 카테고리는 탐색 바에서 제외한다. 표시 가능한 메뉴가 없으면 빈 메뉴 안내와 재조회 동작을 제공한다. 장바구니의 기존 처리와 최종 서버 검증 계약은 유지한다.
8. **장바구니:** 필터는 화면에 표시할 메뉴만 바꾼다. 다른 카테고리에서 담은 메뉴도 장바구니 전체 수량·금액·미리보기에 계속 포함한다. 메뉴별 수량과 메모를 필터 변경 때문에 삭제하지 않는다.
9. **접수 중지:** CLOSED 안내와 기존 주문 현황 분기를 유지한다. 카테고리 선택으로 메뉴/신규 주문 금지 분기를 우회하지 못하게 한다.

## 4. 구현 범위와 순서

### 1단계 — 카테고리 선택과 고정 배치

- `direct_order_storefront_screen.dart`에 선택 카테고리 ID, 공통 표시 목록, 카테고리 선택 처리를 추가한다.
- 메뉴 영역을 `Column(카테고리 바, Expanded(기존 메뉴 Stack))` 형태로 구성한다. 기존 최대 폭 920과 하단 장바구니 동작을 유지한다.
- `전체`와 개별 카테고리를 같은 표시 목록에서 렌더링한다. 필터 변경 시 메뉴 목록을 맨 위로 이동하고 수량 변경 시에는 위치를 유지한다.
- 기존 QR의 `ChoiceChip`·선택 접근성 패턴을 참고한다. 서로 다른 주문 화면의 상태를 공유하거나 QR 화면을 함께 개편하지 않는다.

### 2단계 — 재조회·다국어·경계 상태

- `_load()`와 `_selectView()`에서 storefront가 갱신될 때 선택 ID의 유효성을 함께 보정한다.
- 메뉴 전용 세로/카테고리 가로 스크롤 상태와 controller 수명주기를 관리한다.
- `direct_order_copy.dart`에 `전체`, 빈 메뉴 안내와 필요한 접근성 문구를 추가한다.
- 카테고리가 많거나 이름이 긴 경우, 메뉴가 0개인 경우, 선택 카테고리가 사라지는 경우를 처리한다.

### 3단계 — 회귀 검증과 설계 문서 정합성

- 배달 storefront 테스트 fixture가 여러 카테고리와 변경된 응답을 제공하도록 확장한다.
- 안정적인 Key를 사용해 카테고리 바와 세로 목록을 구분한다. `ListView` 개수나 순서에 의존하는 기존 테스트가 있는지 확인한다.
- 구현 시 기존 `UI_SPEC.md`에 고정 위치, 기본 `전체`, 필터·장바구니·빈 상태 계약을 반영한다. 현재 이 계획을 이미 구현된 사양으로 표기하지 않는다.

예상 수정 범위는 storefront 화면, 화면 전용 copy, 관련 widget 테스트, 기존 UI 사양이다. 현재 데이터 계약으로 해결할 수 있으므로 이 계획에는 DB migration·Edge Function 변경을 포함하지 않는다.

메뉴 검색, 추천·인기 순위 생성, 카테고리별 이미지, 장바구니 화면 개편은 이번 완료 조건에 포함하지 않는다. 카테고리 탭을 눌러 전체 목록의 위치로 점프하고 스크롤에 따라 선택을 자동 변경하는 방식은 별도 복잡성이 있어 이번에는 선택 필터 방식을 사용한다.

## 5. 완료 기준과 검증

| 검증 항목 | 통과 기준 |
|---|---|
| 첫 화면 | 메뉴 목록 위에 `전체 + 매장 카테고리`가 보이고 `전체`가 선택되어 있다. |
| 필터 정확성 | 카테고리 선택 후 다른 카테고리 메뉴가 표시되지 않는다. `전체`는 기존 공개 범위만 복원한다. |

| 운영 흐름 회귀 | CLOSED 안내, 기존 주문 현황, 수기 배송지, 견적·입금 안내의 관련 기존 테스트가 통과한다. |

1. 변경 Dart 파일 `dart format`, `flutter analyze`.
2. 새 카테고리 행동 테스트 및 `test/direct_delivery_storefront_widget_test.dart`, `test/direct_delivery_ui_contract_test.dart`, `test/direct_delivery_regression_isolation_test.dart`, `test/menu_language_switch_test.dart` 실행.
