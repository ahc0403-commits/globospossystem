# 고객 주문 5개 수정 운영 릴리스 계획 (2026-10-23)

이번 릴리스는 선택 상세주소, 승인 전 증빙 교체, 채팅 자동 갱신, VietQR 은행 앱 연결, 관리자 전용 메모 분리만 포함한다. 다른 작업 폴더의 미커밋 변경은 포함하지 않는다.

1. PR의 필수 `POS release contract` 통과 후 main에 병합한다. 병합 SHA에서도 같은 필수 검사가 성공해야 한다.
2. 깨끗한 배포 작업 사본을 최신 origin/main과 동일한 SHA로 맞추고 공식 Supabase CLI로 운영 프로젝트에 연결한다. Vercel 대상도 고정 프로젝트인지 확인한다.
3. 공식 `scripts/deploy_pos_production.sh --db-only`의 dry-run을 확인하고 주소·증빙 마이그레이션 20261023120000을 적용한다. 이어서 같은 절차로 채팅·메모 마이그레이션 20261023121000을 적용한다. 각 파일은 원자적 사후 검증을 포함하며 이력 등록을 확인한다.
4. 공식 배포 스크립트의 기본 경로로 Edge와 웹을 배포한다. Auth 준비 상태, 테스트 데이터 위생, 정적 분석, Edge·Flutter 회귀, CORS·보안 검사, 운영 HTTP 및 고정 운영 계정 로그인 검사를 모두 통과해야 한다.
5. 배포 후 프로젝트·배포 SHA와 마이그레이션 이력, 주소 제약/함수, 증빙·채팅 RPC 권한, 채팅 트리거, 메모 대상 필터를 운영에서 확인한다. 운영 고객·주문·매출에 영구 테스트 데이터를 만들지 않는다. 실제 모바일 은행 앱과 송금, 기존 고객 증빙의 실제 교체·승인은 별도 현장 검증 범위로 명시한다.

실행 로그는 비밀을 제외하고 별도 배포 증거에 보존한다. 마이그레이션 실패 시 해당 트랜잭션이 롤백되며 후속 단계를 진행하지 않는다. DB 적용 후 웹 실패 시 이전 클라이언트용 v1/v2 계약은 유지되지만 새 기능 완료로 보고하지 않는다. 이력 확인 없이 재적용하거나 게이트를 우회하지 않는다.
