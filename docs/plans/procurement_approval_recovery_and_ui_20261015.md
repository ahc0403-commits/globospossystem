# PR 승인 이력 복구 및 스토어 매니저 결재 화면 개선 계획

2026-10-15 사용자 요청 및 첨부 화면 2장 기준.
승인 이력/Office 인계 수정과 첨부 화면 개선의 구현·검증 결과를 함께 관리한다.
사용자가 승인 이력/Office 진입 검증 후 첨부 계획의 구현까지 요청해, 이번 작업의 구현 범위에 포함했다.
소스 구현·로컬/필수 CI·실계정 후보 검증·운영 배포와 배포 후 실제 화면 확인을 모두 완료했다.

## 1. 승인 이력과 다음 결재 단계

- 매장 승인 후 PR은 `office_review`로 이동하고 Office 구매 담당 결재함에서
  같은 PR 번호·개정으로 조회돼야 한다. PR/PO를 복제하거나 강제 재승인하지 않는다.
- 매장 관리자의 처리 이력은 현재 단계와 무관하게 승인·반려 이벤트로 보존한다.
  목록의 상태 배지에서 다음 처리 단계인 구매팀 검토를 구분하고,
  상세 처리 이력에서 매장 승인 시각과 승인자를 확인한다.
- 화면의 **승인완료**는 매장 관리자가 승인한 내역을 포함한다. 여기서 구매팀 검토
  중인 건에는 `매장 승인 완료 · 구매팀 검토 대기`를 표시하고, Office 최종 승인과
  구분한다. `approved` 상태만 조회해 중간 단계 PR을 숨기는 오류를 재발시키지 않는다.
- 권한은 requester → Store Manager → Office buyer 순서를 유지한다.
  BM 승인 단계를 추가하지 않으며, 기존 문서/결재/입고 이력과 자기승인 금지를 유지한다.

## 2. 첨부 1: 상단 도구와 불필요한 영역 정리

- 스토어 매니저 PR 결재 화면에서 `구매 운영 지표·담당자` 영역을 제거한다.
- `과거 발주 조건 검토` 진입 버튼을 이 화면에서 제거한다.
- `내 결재 대기` 필터를 제거한다. 승인대기·승인완료·반려 탭이 처리 범위를
  명확하게 결정하도록 해, 숨은 필터 때문에 승인 이력이 누락되지 않게 한다.
- `구매요청 작성` 버튼을 화면 우측 상단에 고정 배치한다.
- `재고·수요 확인`을 **재고 조회**로 바꾸고, 구매요청 작성 버튼 바로 왼쪽에 둔다.
  재고 조회는 필요할 때 열며 PR 결재 목록을 가리지 않는다.
- 첨부의 구매 유형·PR 검색·기간 필터를 유지하고, 화면이 좁으면 읽기 순서대로
  줄바꿈한다. 주요 버튼·필터가 서로 겹치거나 화면 밖으로 나가지 않게 한다.
- 화면에서 제거하는 항목의 기존 데이터/감사 기록을 삭제하지 않는다.

## 3. 첨부 2: 목록 정렬과 정보 구조

- 구매요청 목록 기본 정렬은 **최신 요청일 내림차순**으로 바꾼다.
  요청일의 기준은 PR 작성일(`created_at`)로 명시하고, 제출일/승인일과 구분한다.
  같은 시각이면 ID를 보조 키로 사용하는 안정적인 커서를 적용한다.
- 탭은 **승인대기 / 승인완료 / 반려**로 간소화한다. 탭별 건수와 목록에 같은
  매장·검색·유형·기간·단계 조건을 사용한다.
- 같은 PR이 반려 후 재제출되면 현재 개정은 승인대기에 배치하고, 이전 반려는 상세
  처리 이력에 보존한다. 탭별 건수에서 같은 현재 개정을 중복 집계하지 않는다.
- 반려는 `returned` 요청과 해당 결재 이벤트를 기준으로 다룬다. 취소를 반려로
  재분류하지 않는다. 취소 이력은 별도 이력/상세 경로에서 보존한다.
- 카드 왼쪽: PR 번호, 요청일·필요일, 품목 수.
- 카드 가운데: 요청자와 소속/역할, 요청 사유. 실제 등록된 계정·직원 연결만 표시하고
  첨부 예시의 이름을 운영 데이터로 하드코딩하지 않는다.
- 카드 오른쪽: `상세 보기` 버튼. 카드 전체 선택도 같은 상세를 연다.
- 긴 사유·이름은 정해진 줄 수 안에 표시하고 상세에서 전체를 확인한다.
  모바일에서는 필드가 세로로 재배치되며 순서와 버튼의 식별성을 유지한다.

## 4. 검증과 조회 방식

- 실제 SM/구매팀 로그인 → 기본 메뉴 → 목록 → 동일 PR 상세를 배포 전후 확인한다.
- 승인 후 대기 목록 제외, 매장 승인완료 이력 유지, Office 결재함의 동일 PR 표시,
  Office 최종 승인 후 이력 보존을 격리 DB의 실제 명령으로 검증한다.
- 운영 확인은 읽기 전용으로 수행한다. 실제 PR 승인/발주/입고를 검증용으로 처리하지 않는다.
- 신규 화면 검증에 최신일/동률 정렬, 다음 페이지 중복·누락, 탭별 건수,
  다른 매장/계정 접근 거부, 390px/1440px 배치, KO/EN/VI를 포함한다.
- 목록은 서버에서 필터/정렬/커서 페이지 처리한다. 기본 20/최대 50건을 유지하고
  요청자는 PR의 기록된 actor 스냅샷으로 함께 반환한다. 카드별 사용자/품목 조회를 추가하지 않는다.
- 상세는 선택 PR만 읽는다. 재고 조회는 사용자가 열 때 실행한다. 갱신 요청을
  병합하고 사용자·매장·필터 범위를 캐시 키에 포함한다. Office는 기존 최대
  100매장 묶음과 동시 2개 일괄 RPC 제한을 유지한다.
- 실제 RPC 수, 반환 행/응답 bytes/경과시간을 기록한다. 실행계획과 운영 측정,
  측정하지 않은 메모리/동시 부하를 구분한다.
