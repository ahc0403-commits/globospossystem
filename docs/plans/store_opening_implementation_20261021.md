### 3 다중 주방과 기존 인계 연결

- `190000`~`193000`: 최대 8개 주방의 순차 경로와 메뉴·주문 채널별 경로를 저장한다.
  서로 다른 메뉴/세트 구성품을 독립 경로로 동시에 처리할 수 있다. 부모 메뉴 경로는 내부
  S/L/면·밥 ID에 상속되며 개별 판매 ID의 명시 경로가 우선한다. 매장 포장 주문도 pickup 경로를 쓴다.
- 각 조리 작업은 실제 주문행/세트 구성품과 구성 버전에 묶인다. 앞 주방이 인계한 수량만
  다음 주방이 시작할 수 있고, 최종 인계만 기존 트레이/층 FIFO 수량을 증가시킨다.
- 전가복은 주방→저장층 준비→고객 서빙을 유지한다. checker를 재활성화하지 않고,
  저장 2F/3F와 고객 1F/2F 표시 및 저장 3F의 두 활성 계정을 보존한다. 분식클럽은 트레이를 유지한다.
  픽업/배달 조리 완료는 테이블 층 준비 lot/층 알림을 만들지 않는다.
- 새 주방 화면은 담당 작업, 명시적 부분 시작/인계, 경과 시간, 최근 24시간 완료 이력,
  아직 다음 단계가 받지 않은 수량의 되돌리기, 기존 포장 업무와 탐색 메뉴를 제공한다.
  요청은 사용자·매장별로 보관하고 같은 UUID/내용으로 재시도한다. 수량 충돌은 자동 반복하지 않고
  미반영 요청을 해제한 뒤 재선택하게 한다.
- 개인 주방별 비공개 실시간 채널과 15초 보조 조회를 사용한다. 새 작업/다음 주방 인계에는
  기존 push 전달 인프라를 재사용하되 해당 주방 계정에만 전달하고, 화면 알림·음성을 제공한다.
  push 전달의 실제 기기 수신은 현장 검증 대상이다. 기존 수동 배달 조리표는 기존처럼 화면 조회를
  기반으로 하며, 신규 주방 화면에서는 준비 수량 변화도 표시한다.
- 부분 취소·조리 후 취소 소모·복원·테이블 분할/전체 이동에서 단계별 수량과 FIFO를 보존한다.
  복원할 때 단계 revision은 증가시켜 취소 이전 화면의 요청이 다시 유효해지는 것을 막는다.
  되돌리기로 무효화된 lot를 이동할 때 유효 수량만 분배하며, 전체 이동도 무효 이력을 유지한다.
  시작/인계/되돌리기는 처리 전후 수량과 실제 행위자를 감사 기록에 남긴다.
- 기존 분식클럽 완료 처리의 암묵적 시작 증가는 기존 호출에서 유지한다. 새 경로는 이미 기록한
  시작 수량을 완료 때 다시 더하지 않는다. 이 차이는 실제 2개 세트/6개 구성품 시험으로 확인했다.
- 새 다중 주방은 화면 운영(paperless) 모드에서만 게시할 수 있다. 기존 단일 주방 출력 운영은
  보존한다. 여러 주방 프린터로 작업을 나눠 출력하는 기능은 이번 신규 경로의 지원 범위가 아니다.
- 되돌리기는 미인계 수량의 잘못된 입력 수정이다. 재조리를 별도 생산·재고 사건으로 추가하는
  기능은 이 작업에 포함하지 않는다.

### 4 게시·장치 확인·전환·복귀

- 초안 저장→현재 설정/메뉴 해시 검증→불변 버전 게시→담당 장치 확인→최고 관리자 전환을
  분리한다. 게시 자체는 영업 흐름을 바꾸지 않는다. 이전 게시 버전을 초안으로 복원한 뒤
  동일한 검증 절차를 거쳐 다시 게시할 수 있다.
- 중복/누락 담당자, 타 매장 계정, 순환/알 수 없는 단계, 중복 메뉴·채널 경로를 거부한다.
  메뉴 가격/노출/내부 부모/경로/선택 정의 및 개점 설정이 바뀌거나 검증이 오래되면 재검증한다.
- 모든 활성 담당 계정의 장치가 후보 버전·미전송 0건을 확인해야 한다. 확인한 장치는
  전환 대기로 들어가 기존 완료 RPC를 통해서도 수량을 진행시킬 수 없다. 확인은 5분간 유효하고
  화면에서 30초마다 갱신하거나 대기를 해제할 수 있다. 사용 종료한 장치는 마지막 미전송이 0건이고
  5분 이상 오프라인일 때 최고 관리자가 명시적으로 등록 해제할 수 있다. 해제 내용은 감사 기록에 남고,
  다음 전환에는 해당 담당 계정의 대체 장치 확인이 필요하다.
- 열린 주문, 승인 대기 직접 주문, 미완료 조리표·트레이/층 인계·남은 음식 포장이 있으면
  전환/복귀를 거부한다. 주문 접수와 전환은 같은 매장 잠금 경계를 사용한다.
  접수가 먼저면 전환이 대기 후 거부되고, 전환이 먼저면 대기하던 주문이 새 버전을 받는다.
- 새 경로가 활성화된 동안 이전 설정/배정 API로 우회 변경할 수 없다. 기존 주문의 구성 버전은
  수정할 수 없으며, 기존 운영으로 복귀한 후 접수한 주문만 기존 경로로 돌아간다.
- 기존 비활성 매장 삭제도 게시 이력·장치·구성 버전이 붙은 주문 때문에 막히지 않는다.
  원래의 최고 관리자/비활성/slug/연결 계정 조건과 감사 기록을 실제 authenticated 역할로 재검증했다.
