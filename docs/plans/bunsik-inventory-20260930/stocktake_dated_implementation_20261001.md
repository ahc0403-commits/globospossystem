# 날짜 기준 재고실사 구현

대상은 분식클럽 빈탄 123개 원료이며 SAMPLE은 검증용이다. 기존 코드 전환과 샘플 초기화는 다시 실행하지 않는다.

## 동작

- 실사 업무일과 재고 기준시각을 Asia/Ho_Chi_Minh로 선택한다. 날짜를 파일명과 시트 상단에 표시하고 서버 세션에 고정한다. 다운로드 시각과 업로드/확정 시각은 별도로 저장한다.
- v2 양식은 실사정보, 재고실사, 작성안내 세 시트다. 사전 다운로드의 POS 수량은 잠정값이다. 초안 이력에서 같은 날짜의 최신 양식을 다시 받을 수 있다.
- 확정 시 동일 기준시각의 POS 재고 B와 실측 A를 비교한다. 이후 거래 M을 보존하여 현재 재고를 A+M으로 계산한다. 기존 quantity에는 음수가 될 수 없는 실사 기준 수량을 저장하고, current_stock에는 이후 소진으로 음수가 될 수도 있는 현재 POS 재고를 보존한다. 관찰시각이 다른 행은 그 사이의 증감으로 기준시각에 환산하고 원래 관찰 수량을 함께 저장한다.
- 모든 실제 current_stock 변경을 DB 트리거로 한 번 기록한다. 기존 inventory_transactions는 원문서와 종류를 연결하는 근거로 유지한다. 직접 수정 누락과 기존 판매/입고 문서 중복 합산을 피하기 위해 캡처된 물리 변화 원장을 사용한다. Office와 기존 결제·입고 함수의 이름과 계약은 유지한다.
- 기존 판매 기록은 동일 주문/결제 시각이 확인된 건만 발생시각을 보완한다. 과거 POS 재고 재구성 값은 미리보기에서 미기록 조정 여부를 확인해야 한다. 미등록 품목은 명시적인 기초재고 등록과 비교 불가 리포트로 구분한다. 시점이 불명확한 과거 증감은 자동 확정하지 않는다.
- 전체 행 검증과 적용은 원자적이며 같은 완료 파일의 재시도는 조정을 추가하지 않는다. 오래된 미리보기는 새 거래를 확인한 뒤 갱신한다. 더 최근 확정 실사 및 뒤늦은 기준시점 이전 거래는 충돌 검토 대상으로 차단한다.
- 이력/날짜별 리포트는 기준 POS, 기준시각 환산 실측, 원 관찰 수량, 차이, 공급처, 단위, 차이 금액과 날짜별 +/-를 제공한다. Excel과 인쇄가 같은 확정 값을 사용한다. 단가 미등록은 0원 손실로 표시하지 않는다. 평가단가는 양식 준비 시 등록된 가격을 고정하며, 과거 날짜의 거래 가격을 복원했다고 주장하지 않는다.
- 이전 v1 파일은 기존 계약으로 식별한다. v1 쓰기 RPC로 v2 세션을 확정할 수 없다.

## 검증

격리 PostgreSQL에서 다음날 +30/-20/-5 후 100 POS/80 실측 → 현재 85, 초안 미반영, 최종 행 오류 전체 취소, 중복 재시도, 동시 쓰기 및 미리보기 갱신, 기초재고/과거 이력 불명확, 관찰시각 환산, 최근 실사 충돌, 원본 리포트 보존과 rollback을 검증한다. Flutter에서는 123행·날짜·시간대·파일 검증·Excel 리포트와 날짜/미리보기/리포트 창의 실제 실행을 검증한다.

운영 마이그레이션과 웹 배포는 exact main GitHub POS release contract 통과 후 scripts/deploy_pos_production.sh로만 진행한다. 운영 반영 여부와 실제 검증 결과는 실행 보고서에서 별도 기록한다. 실사 수량은 사용자가 조사한 결과만 입력하며 테스트 수량을 빈탄 운영 DB에 확정하지 않는다.
