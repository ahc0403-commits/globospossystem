# 날짜 기준 재고실사 양식·소급 반영·증감·차이 리포트 계획

작성: 2026-10-01 · 기준 시간대: Asia/Ho_Chi_Minh · 대상: 분식클럽 빈탄 123개 원료. SAMPLE은 검증용 매장.

**결정: 양식 다운로드, 실사 기준일/시각, 업로드 검증, 이후 재고 증감 보존, 실사 리포트를 하나의 기능으로 확장한다.** 다음날 영업이 시작돼도 전날 실측 재고에 이후 거래를 더하고 빼서 현재 재고를 계산해야 한다. 날짜만 표시하거나 업로드 시점의 현재 재고를 실측값으로 덮어쓰는 방식으로는 이 요구를 충족하지 못한다.

이 문서는 확장 기능의 설계 기록이다. 소급 반영과 리포트를 구현하고 운영 DB·웹 반영 및 검증을 완료했다. 최신 상태와 실제 사용 순서는 [날짜 기준 실사 실행 보고서](/Users/andreahn/globos_pos_system/docs/plans/bunsik-inventory-20260930/stocktake_dated_execution_report_20261001.md)를 따른다. 아래 표의 현재 기능은 계획 수립 당시 v1 배포 상태이며, 기존 코드 전환·샘플 복제 완료 사실은 유지한다.

## 2. 날짜와 기준시각을 명확히 기록하는 다운로드

다운로드 전에 매장, **실사 업무일**, **실사 기준시각**을 선택한다. 기준시각은 그 수량이 존재한 시점이다. 마감 후 실사는 실제 마감·입출고 종료를 확인한 시각으로 지정하고, 일괄적으로 23:00이나 다운로드 시간을 대신 넣지 않는다. 업무일과 달력 날짜는 자정 이후 마감 시 다를 수 있으므로 둘 다 보존한다.

| 날짜 필드 | 의미 | 입력/관리 |
|---|---|---|
| count_business_date | 어느 영업일의 실사인지 | 다운로드 화면에서 선택하고 세션에 고정 |
| effective_at | 수량의 기준시각, 초까지 포함 | Asia/Ho_Chi_Minh 표시, DB는 timestamptz |
| observed_at | 해당 품목을 실제로 센 시각 | 공통 시각 또는 품목별 기록 |
| exported_at | 양식 생성 시각 | 서버 기록, 실사 기준시각과 구분 |
| uploaded_at / completed_at | 파일 업로드/확정 시각 | 서버 기록, 업무일을 이 시각으로 바꾸지 않음 |

파일명 예: `Bunsik_BinhThanh_재고실사_2026-09-30_2300_<세션식별자>.xlsx`. 시트 상단에는 **매장명 / 실사 업무일 / 기준시각 / 시간대 / 생성시각**을 사람이 읽을 수 있는 형식으로 표시한다. 파일명만으로 날짜를 해석하지 않는다.

양식은 세 시트로 제공한다.

- **실사정보:** 위 날짜, 매장/세션/양식 버전, 단위와 입력 안내. 파일의 날짜·매장 정보는 서버의 고정 세션 값과 대조한다.
- **재고실사:** 123개 UUID·코드·품목명·공급처·기준단위, 실사 기준시점 POS 재고, 입력할 실측 수량, 실제 관찰시각, 제외 사유, 비고. 실측 수량은 빈칸으로 시작한다. POS 기준 수량은 서버에서만 계산한다.
- **작성안내:** 입력할 셀 색상, 빈칸/0의 차이, g/ml/ea 및 kg/L 변환, 여러 보관장소 수량 합산, 날짜 수정·오류 처리 안내.

품목 코드·ID·단위·기준일의 편집 금지 표시는 편의 기능이다. 보안은 서버 검증으로 보장한다. 단위/환산값은 다운로드 시점에 고정하고, 신규 음료·포장재와 구매 비활성 품목도 실사 대상에 포함한다. 파일 재다운로드 시 원래 실사 기준일/시각을 유지하며 새 업무일로 몰래 바꾸지 않는다.

일차 버전은 마감 후 공통 기준시각 실사를 지원한다. 품목을 세는 도중 거래가 있었다면 관찰시각과 기준시각 사이 거래를 별도로 환산·검증해야 한다. 이 검증 없이 서로 다른 시간의 수량을 같은 기준시점의 수량으로 간주하지 않는다. 실사 당일 전에 양식을 받는 예약 방식이라면 기준시점에 장부 재고를 서버에서 확정하며, 사전 다운로드의 POS 수량은 잠정값으로 표시한다.

## 3. 전날 실사와 다음날 영업을 함께 반영하는 규칙

품목별로 아래 값을 구분한다.

- **T:** 실사 기준시각. **U:** 확정 작업 시각.
- **B(T):** 실사 기준시점의 POS 장부 재고.
- **A(T):** 입력한 해당 시점의 실측 재고.
- **M(T,U]:** T 이후 U까지의 유효 재고 거래 합계. 입고/반입/재고 증가 조정은 +, POS 레시피 소진/폐기/반출/공급처 반품은 -.
- **D = A(T) − B(T):** 실사 차이. 양수는 장부보다 많음, 음수는 부족.

**현재 재고 = A(T) + M(T,U]**

거래 이력과 현재 재고가 일치하면 같은 결과를 **확정 직전 현재 POS 재고 + D**로 반영할 수 있다. 이렇게 실사 차이만 적용하면 다음날의 판매·입고를 다시 실행하거나 지울 필요가 없다. 재고가 변했다는 이유만으로 정상적인 다음날 거래를 오류로 처리하지 않는다.

다음은 가상 수량 예시다.

| 단계 | 수량(ea) |
|---|---:|
| 9/30 실사 기준시점 POS 재고 | 100 |
| 같은 시점 실제 조사 재고 | 80 |
| 실사 차이 | -20 |
| 10/1 입고 | +30 |
| 10/1 POS 판매 소진 | -20 |
| 10/1 폐기 | -5 |
| 10/1 업로드 직전 POS 현재 재고 | 105 |
| 업로드 반영 후 현재 재고 | **85 = 80 + 30 - 20 - 5 = 105 - 20** |

보고서는 9/30의 POS 100/실제 80/부족 20을 유지하고, 10/1의 +30/-20/-5를 따로 보여준다. 현재 재고를 단순히 80으로 설정하면 다음날 거래가 없어지므로 허용하지 않는다.

확정 처리에서는 세션과 해당 품목 재고를 일정한 순서로 잠근다. 잠금 후 서버가 T의 장부 재고와 T 이후 거래를 다시 조회하고, 파일 미리보기의 거래 버전이 변했으면 변경분을 보여준 뒤 새 미리보기를 요구한다. 전체 행 검증·실사 조정·세션 완료·보고서 확정은 한 트랜잭션으로 처리한다. 업로드 중 판매는 정상 처리하고, 재고 갱신이 겹치는 짧은 구간만 기존 재고 잠금 계약을 따른다. 결제 완료를 Excel 처리나 외부 서비스에 의존시키지 않는다.

## 4. 거래 기준일·이력 정합성 보강

기존 `inventory_transactions`를 재고 증감의 단일 원장으로 활용한다. 기존 물리 테이블/FK와 Office 조회 계약은 유지한다.

1. 거래에 발생시각 `effective_at`, 업무일 `effective_date`, 기록 시각 `created_at`, 기준단위 수량, 원문서/원품목 참조, 재고 전후 수량을 명확히 기록한다. 실사 조정은 T와 선택한 업무일에 귀속하되 생성 시각은 실제 확정 시각으로 남긴다.
2. 판매 소진·확정 입고·폐기·반품·수동 조정 등 모든 실제 재고 갱신 경로가 같은 트랜잭션 안에서 원장도 기록하는지 점검한다. 직접 재고 수량을 바꾸고 원장이 남지 않는 경로는 소급 반영 전에 보완한다. 기준시점/이후 거래 합계와 현재 재고를 대조한다.
3. 일별 소진 집계 `inventory_daily_consumption`은 분석용으로 유지한다. 이미 판매 차감 원장에 기록된 소진을 일별 집계로 또 빼지 않는다. 입고도 입고 문서와 restock 거래를 중복 합산하지 않는다.
4. 기존 원장의 업무시각은 주문·결제·입고·조정 원문서와 연결해 가능한 범위에서 검증·보완한다. 근거가 없는 과거 시각을 임의 생성하거나 무조건 `created_at`으로 확정하지 않는다. 기준시점 POS 재고가 복원 불가능하면 '기준재고 확인 필요'로 표시한다.
5. 실사 기준시각에 POS 소진/입고 처리 큐가 아직 밀려 있다면 기준 재고를 확정하기 전에 대기 거래를 확인한다. T 이전 발생 거래가 다음날 늦게 기록된 경우에는 실측 재고에 이미 포함된 거래인지 구분해야 한다. 단순히 업로드일 기준으로 모두 차감하지 않는다.
6. 완료된 실사 이후 늦게 도착한 T 이전 거래는 최근 실사 기준점에서 현재 재고를 재계산해 중복 차감하지 않는 정책을 구현한다. 원본 실사 보고서는 보존하고 장부 비교 변경은 이력 버전/추가 검증 상태로 기록한다. 이 처리가 검증되기 전에는 지연 거래가 미해결인 세션의 자동 확정을 허용하지 않는다.

실사 전에 다운로드할 수 없었던 과거 날짜도 선택할 수 있게 설계한다. 다만 그 날짜의 POS 재고가 검증 가능할 때만 일반 실사 차이를 자동 반영한다. 실사일 이후 등록된 19개 같은 품목은 '당시 POS 미등록/기준재고 없음'으로 구분한다. 이를 자동으로 POS 재고 0으로 간주해 부족/초과를 계산하지 않는다. 해당 품목의 실측 수량을 기초재고로 설정하는 절차를 명시적으로 제공하고, 차이 리포트에는 비교 불가로 표시한다.

T 이후에 더 최근의 확정 실사가 있는 품목은 이전 실사 파일의 일반 소급 반영을 막는다. 과거 기록 등록/정정으로 구분해 처리하고 최신 실재고 기준점을 덮어쓰지 않는다. 단순 입고·판매 증감과 새로운 실사 기준점을 같은 종류의 거래로 합산하지 않는다.

## 5. 업로드 검증과 사용자 미리보기

사용 순서: **빈탄 선택 → 실사 업무일/기준시각 선택 → 양식 다운로드 → 수량 입력 → 업로드 검증 → 차이·이후 증감 미리보기 → 임시저장/확정 → 리포트**.

확정 전 반드시 다음을 검증한다.

- 선택한 매장, 세션, 양식 버전, 업무일, 기준시각, 시간대가 서버 세션과 일치하는지. 업로드한 파일명이나 업로드 날짜로 기준일을 덮어쓰지 않는다.
- 품목 UUID/코드/단위·환산, 중복/누락 행, 수식, 음수 실측 수량, 범위를 넘는 값, 소수 자릿수. 0과 미입력을 구분하고 제외 사유를 요구한다.
- 전체 실사 범위, 원장에 없는 재고 변경, 지연·취소·환불 거래, 새 실사와의 충돌. 오류는 시트/행/코드/원인으로 설명한다.
- 원장 합계와 현재 재고의 불일치가 있으면 자동 확정을 차단하되 입력 파일과 초안은 보존한다. 정상 영업 거래가 존재한다는 이유만으로 차단하지 않는다.
- 같은 파일·세션의 동일 확정 재시도는 기존 결과를 반환한다. 내용이 다른 완료 파일은 새 정정 버전으로 처리하고 중복 조정을 만들지 않는다. 임시저장은 재고를 바꾸지 않는다.

미리보기에는 **기준일 / 실사 기준 POS 수량 / 실측 수량 / 차이 / 이후 입고+ / 판매·폐기- / 반영될 현재 수량**을 함께 표시한다. 장부 재고나 이후 거래는 Excel 셀 값을 신뢰하지 않고 서버에서 계산한다. 정상 거래가 많아 확정 직전 결과가 달라지면 갱신된 차이를 보여준다. 실측은 음수가 될 수 없지만 이후 소진으로 계산된 현재 재고가 음수가 되는 경우는 숨기거나 0으로 자르지 않고 재고 부족으로 표시한다.

## 6. 재고실사 리포트

기존 실사 탭에 **실사 이력 / 실사 결과 / 기준일 이후 증감**을 추가한다. 빈탄 매장과 실사 업무일/세션을 선택해 조회하고, 같은 데이터로 Excel 리포트를 내려받는다. 인쇄 화면도 동일한 확정 결과를 사용한다.

실사 결과의 품목별 필수 열:

| 코드·품목·공급처 | 기준단위 | 기준시점 POS 재고 | 실측 재고 | 차이(실측−POS) | 부족/초과 | 기준 단가 | 차이 금액 | 실측시각·제외 사유 |
|---|---|---|---|---|---|---|---|---|

요약에는 대상/실사/미입력/제외 품목 수, 부족/초과 품목 수, 부족 금액·초과 금액·순차이 금액을 표시한다. g·ml·ea를 섞어 하나의 재고수량 합계로 만들지 않는다. 가격 없는 신규 19개 등은 '단가 미등록/금액 계산 제외'로 표시하며 0원 손실로 보이지 않게 한다. 단가는 실사 기준의 확정 평가값을 저장하고 나중의 공급가격 수정이 과거 리포트를 바꾸지 않게 한다. POS 재고가 0 이하일 때 차이율을 억지로 계산하지 않는다.

기준일 이후 증감 화면에는 **실사 기준 재고 → 날짜별 입고+ / 판매 소진- / 폐기- / 반품- / 조정± → 해당 날짜 말 재고 / 현재 재고**를 표시한다. 각 증감은 원래 주문/입고/폐기 문서로 추적한다. 실제 재고가 마지막으로 측정된 T와 이후 계산된 현재 재고를 구분해, 다음날 계산값을 다음날 실측값이라고 표시하지 않는다.

확정 당시 POS 재고·실측·차이·평가단가·처리자·업로드/확정 시각은 리포트에 고정한다. 이후 거래 목록은 조회 종료시각까지 확장된다. 초안은 '미확정', 제외 품목은 '미조정', 과거 장부 자료가 없는 품목은 '비교 불가'로 표시한다. 정정/취소는 별도 이력을 남기고 이미 확정된 원본을 조용히 수정하지 않는다.

## 7. 구현 순서와 완료 조건

1. **이력 보강과 날짜 계약:** 모든 재고 갱신 경로/원장 부호/발생시각/취소 정책/기준점 재구성 점검. 검증 가능한 소급 기준일 범위를 확정한다.
2. **다운로드 v2:** 날짜·시각 선택 UI, 서버 세션 날짜 고정, 123개 양식과 읽기 쉬운 안내/파일명, 새 양식 버전과 재다운로드 동작.
3. **업로드와 기준일 반영:** v3 RPC로 미리보기/임시저장/완료 구현, 원장 대조 후 현재 수량에 실사 차이만 반영. 기존 v1 세션·파일은 별도 호환 경로로 식별하며 날짜 의미를 자동 변환하지 않는다.
4. **리포트:** 확정 이력 조회, 기준시점 POS/실측 차이, 이후 일별 +/-와 현재 계산 재고, 보고서 Excel 내보내기.
5. **SAMPLE 검증 → 빈탄 배포:** 실측 데이터 대신 가상 수량으로 테스트하고 롤백한다. 통과 후 저장소 규칙에 따라 exact main GitHub 필수 검사와 `scripts/deploy_pos_production.sh`로 DB/웹 배포한다. 빈탄의 실제 확정은 사용자가 조사한 수량으로 진행한다.

필수 인수 검증:

- 9/30 실사 → 10/1 영업·입고·폐기 후 업로드: 예시처럼 현재 재고 85, 리포트는 9/30 POS 100/실제 80/차이 -20, 다음날 +30/-20/-5 보존.
- 다운로드일/업로드일/업무일이 다름, 자정 이후 영업 마감, UTC와 베트남 날짜 경계, 기준시각 경계에 동시 거래가 발생한 경우.
- 실사 관찰시각이 품목마다 다르거나 조사 도중 재고 이동이 있었을 때 기준시각 환산/차단 안내가 올바름.
- 다운로드 전후 코드/단위 변경, 날짜/매장 조작, 123행 중 마지막 행 오류: 부분 반영 0건.
- 동시 판매/확정 입고, 확정 직전 원장 변경: 증감 누락과 중복 없이 재계산/갱신 미리보기.
- 동일 파일 재시도·중복 업로드·다른 파일로 같은 완료 세션 수정: 조정 한 번만 실행, 원본 결과 보존.
- T 이전 지연 결제/입고, 취소·환불·반품, 직접 변경돼 원장과 맞지 않는 재고: 잘못된 소급 확정 없음.
- 신규 품목의 과거 POS 재고 없음, 미실사/0/제외, 기준단위 3자리 소수, 단가 없음, 음수 POS/이후 계산 재고, 서로 다른 단위 합계 처리.
- T 이후 새 확정 실사가 존재: 오래된 파일이 최신 실측 재고를 덮어쓰지 않음.
- 리포트를 날짜·세션으로 재조회하고 Excel로 내려받아도 확정 당시 POS/실측 차이가 변하지 않음. 판매 소진·입고 합산이 두 번 이루어지지 않음.
