## 확인한 원인

## 개선 순서와 완료 기준

### 1. 전가복 회사명 조회 복구 — 최우선

- 실행 시점에 전가복 ID·활성 상태·현재 설정을 다시 읽고, 해당 매장만 활성화하는 멱등적 변경을 준비한다. 타 매장 설정은 유지한다.
- 변경 전 행 존재 여부와 값을 기록한다. 되돌릴 때 기존 행이 없었으면 생성한 행만 제거하고, 기존 값이 있었으면 그 값으로 복원한다.
- 실제 전가복 cashier 계정에서 `0313431011` 입력 후 필드 이탈/조회 버튼으로 회사명과 출처 표시를 확인한다. 사용자가 입력한 주소·이메일·전화는 보존되어야 한다.
- 취소 시 저장하지 않고, 명시적 제출 시에만 구매자 정보가 저장되어야 한다. 결제와 비동기 MISA 발행 경로는 기존 계약을 유지한다.

### 2. 매장별 상태 안내와 설정 누락 방지

- 현재 접근 가능한 매장에 한해 조회 가능 상태를 반환하는 제한된 RPC/설정 응답을 제공한다. 브라우저에 내부 설정 테이블의 직접 조회 권한을 열지 않는다.
- 폼 진입 시 비활성이면 조회 버튼을 비활성화하고 수동 입력 안내를 먼저 표시한다. 서버의 실제 조회 시점 권한·활성 상태 검사는 유지한다.
- 슈퍼 관리자용 설정과 변경 감사 기록(매장·이전/새 값·작업자·시각)을 추가하고, 매장 개설 체크리스트에 조회 사용 여부를 포함한다. 모든 매장을 자동 활성화하지 않는다.
- 한국어·베트남어·영어에서 ‘회사명 조회’의 범위와 주소·연락처 수동 입력을 명확히 안내한다.

### 3. 주소 자동 입력은 별도 확장

- 회사명 복구와 분리한다. 공급자의 주소 제공 범위·최신성·사용 조건과 응답 계약을 검증한 뒤 도입 여부를 결정한다.
- 도입한다면 출처와 조회 시각을 표시하고 기존 수동 입력을 덮어쓰지 않는다. 전화·이메일을 사업자번호만으로 추정하거나 채우지 않는다.

## 성능 및 보안 계약

- 현재 성공 경로: 클라이언트 요청 1회, Auth 확인 1회, claim RPC 1회, release RPC 1회, 외부 GET 최대 2회 순차 실행. 비활성 경로는 외부 GET 0회다.
- 외부 공급자 합산 5초, 각 응답 최대 64 KiB, 자동 재시도 없음. 사용자당 60초에 10회, 전체 동시 lease 2개와 10초 만료를 유지한다.
- 성공 캐시는 세션·매장·번호·공급자 정책에 따라 분리하고 5분/50개 및 진행 중 요청 공유를 유지한다. 목록별 업체 조회를 추가하지 않는다.
- 새 상태 조회는 선택 매장당 1회로 제한하고 세션/매장 변경 및 설정 변경 시 무효화한다. 관리자 목록은 페이지 단위 JOIN/일괄 조회로 구현한다. 행마다 원격 요청하지 않는다.
- 전체 동시 2개 제한은 매장 증가 시 병목이 될 수 있다. 부하 검증에서 활성 매장 수·동시 사용자 수별 지연과 제한 응답률을 측정한 뒤 조정한다. 이번 단일 공급자 측정으로 용량이 충분하다고 판단하지 않는다.

## 검증 및 실행 의존성

이번 조사에서 Deno handler 테스트 9개와 Flutter 회사명/구매자 폼 테스트 21개가 통과했다. 운영 SQL은 설정과 함수 정의만 읽었다. 운영 cashier UI, 운영 Edge 버전, 변경 후 저장·발행, Windows 기기 검증은 수행하지 않았다.

구현 시 비활성/활성/권한 거부/타 매장 접근/제한 초과/공급자 오류, 중복 요청, 세션·매장·번호 변경 중 늦은 응답, 사용자 수정 보존을 로컬에서 검증한다. 설정 상태 조회의 실제 호출 수·응답 크기·지연도 측정한다. DB 격리 fixture로 권한과 설정 변경 회귀를 확인한다.

`scripts/verify_pos_recipient_buyer_lookup_bounded_release.sql`은 활성 매장이 정확히 1개라고 검사하지만 현재 운영은 이미 2개다. 추가 활성화 전 이 스크립트의 호출처와 적용 범위를 확인하고, 현재 정책에 맞는 매장별 검증으로 개정·검증해야 한다. 과거 마이그레이션 자체의 역사적 검사를 임의로 제거하지 않는다.

소스 기준 HEAD는 `58e0fa8f95117874ed9ebe71b8479cf066dc0c96`이며 작업 공간에 기존 변경이 많다. 위 테스트는 현재 작업 공간 조사 증거이고 깨끗한 최종 SHA 릴리스 증거가 아니다. 구현 시 최종 SHA에 로컬 검사 로그·환경·시간·종료 코드·산출물 해시를 연결하고 원격 push SHA를 확인한다. 운영 릴리스는 깨끗한 최신 exact-main 및 `scripts/deploy_pos_production.sh` 공식 경로와 실제 로그인/기능 검증을 따른다. 배포 스크립트의 GitHub check-run 의존성은 별도 해결 항목이며 우회하지 않는다.
