# 전체 매장 매출 신고 — 2026-10-21

매출신고의 현금/마감 집계와 매장 선택은 분식클럽 브랜드 ID에 고정돼 있었다.
MISA 원본은 전가복 실매출을 이미 동일 AKJ 법인으로 집계했지만 화면에는 매장 구분이 없었고,
전가복의 시스템 물티슈 품목에는 승인된 item-type 매핑이 없었다.

## 구현

- `20261021140000_all_store_sales_reporting.sql`은 두 요약 RPC overload를 함께 갱신한다.
  등록된 실매장을 브랜드에 관계없이 표시하고, 판매가 있었던 비활성 매장도 보존한다.
  등록일 이후의 날짜에만 무매출 매장을 노출하고, 법인 이력을 결제/판매시각에 적용한다.
- 기존 `bunsik_*` JSON 필드는 구버전 클라이언트 호환을 위해 유지하되 전체 식당을 의미한다.
  실제 결제 또는 마감이 있는 매장만 현금 마감 대상이며, 무매출 신규 매장이 합계를 막지 않는다.
  신규 매장은 별도 허용 목록이나 재배포 없이 자동 표시된다.
- 매장별 영수증 수, 총매출, 현금/이체/카드·기타, 공급가/VAT, 마감 상태,
  판매품목 매핑 누락 수와 자동 매핑 정책 여부를 같은 요약 응답에서 표시한다.
  미설정 법인 계좌도 표시하며, 신규 정책 승인이나 계좌를 자동으로 꾸미지 않는다.
  기존 메뉴 등록의 승인 정책 기반 자동 매핑은 유지한다.
- 자동 조회에서 기존 목록과 다운로드 결과 메시지를 지우지 않는다.
- MISA workbook builder, VAT/할인/결제 분류, 영수증별 계산서, 원본/발행 스냅샷,
  샘플/비매출 제외, 확정된 무결성 실패 시 차단 규칙은 변경하지 않는다.
- 전가복 물티슈 매핑은 실제 로그인한 관리자가 기존 JSON 승인 화면에서 등록했다.
  기존 AKJ의 `Khăn ướt / Cái` 규칙과 동일하며 2026-10-21 HCM 00:00부터 무기한 유효하다.
  `JGB-WET-TISSUE-20261021-v1`에 실제 승인자가 기록됐음을 운영 DB에서 확인했다.

## 검증

- 관련 Flutter 100개, 전체 정적 분석 통과.
- 격리 SQL에서 실제 migration을 두 번 적용했다. 신규 브랜드/무매출/미래 등록,
  분할 결제/비매출 제외, 물티슈 누락 표시, 비활성·법인 변경 이후 과거 귀속,
  두 overload 호환성과 권한 경계를 검증했다.
- 소유한 격리 Docker DB의 합성 5/50/500매장과 1천/1만/10만 결제를 측정했다.
  단일 요약 서버 시간은 약 20/82/698ms, 응답은 7/24/198KB였다.
  동시 20명의 p95는 약 172/445/4652ms였다. 500매장 실행 계획의 관계 스캔은
  반복을 포함해 622,498행이었다. 21회 요청에 요약 함수 호출은 21회이고
  export fingerprint 호출은 0회였다. 운영 성능 측정과는 구분한다.
- 요약은 날짜별 1 RPC, 상세/엑셀은 기존 100건 커서 페이지와 최대 2개 동시 소스 조회를 유지한다.
  요약/내보내기에 매장별 RPC를 추가하지 않는다.
- 실제 엑셀과 운영 배포 결과는 로컬 release evidence에 별도 기록한다.
  원본 엑셀과 구매자 정보는 Git에 넣지 않는다.

## 어제 원본과 비교

기준은 매출 자동화 앱의 `runtime/runs/2026-10-20/MISA.xlsx`다.
`Hóa đơn GTGT` 17열, 8행 헤더, 안내 1~7행, `POS Ledger` 14열,
`Invoice Mapping` 13열, `Export Contract` 2열 구조를 비교한다.
`scripts/compare_misa_workbook_structure.py`는 헤더/열/병합/열 배치/계약 버전과
숫자·문자 자료형을 검사하며 날짜·금액·거래 수에 따른 행 수 차이는 별도 보고한다.

어제 파일을 운영 화면에서 다시 다운로드하는 시도는 기존 `data_integrity_failed`
최종화(마감 이후 결제 5건) 때문에 차단됐다. 확정 기록을 변경하거나 검사에서 제외하지 않았고,
실제로 보존된 어제 파일을 비교 기준으로 사용한다.

실제 오늘 다운로드(54영수증/273출력행)와 어제 원본(310영수증/680출력행)을 비교한 결과
구조 차이는 0건이었다. 신고/감사 헤더, 안내문, 열 배치, 병합, 계약 버전과 자료형이 동일하다.
오늘 파일에 전가복 18개 출력행과 물티슈 품목이 포함됨을 확인했고, 감사행 수는 신고행 수와 일치했다.
헤더를 의도적으로 바꾼 사본은 비교 스크립트가 실패로 판정해 변화 검출도 확인했다.
