# 배달·포장 콤보 주문 및 금액 화면 개선 — 2026-10-13

사용자 요청 범위는 최종 금액 전송 버튼 통합, 배달비 안내 한 줄 표시, 배달 화면 콤보 주문 지원이다. checker 전달은 사용자의 확인에 따라 제외했다. 이 문서는 소스 계약이며 운영 적용 증거는 별도 배포 보고서에 기록한다.

## 화면

배달·포장 모두 공통 견적 메모 아래 전송 버튼을 하나만 표시한다. 기존 처리 중 잠금과 고객 요청사항 확정 조건을 유지한다. 금액 상세에서 배달비 문구를 한 번만 출력하고 포장에는 숨긴다. 새 안내는 “배달비는 주문 금액에 포함되지 않습니다.”이며 KO/VI/EN을 지원한다. 과거 배달비 포함 견적의 지급 안내는 유지한다.

콤보 수량 × 콤보당 음료 수만큼 선택해야 장바구니에 담을 수 있다. 같은 음료의 반복 선택과 여러 음료 혼합 선택을 지원한다. 수량 변경 시 기존 선택을 보여주고 다시 확인한다. 선택 취소는 장바구니를 변경하지 않는다. 장바구니, 고객 주문 상세, 캐셔, 견적 PDF에 저장한 음식·음료 구성을 표시한다.

## 서버 및 호환성

`storefront_v3`는 매장 범위의 메뉴를 `(sort_order,id)` 커서로 최대 200개씩 조회한다. 음료 옵션은 페이지당 한 번 전송하고 콤보마다 공유한다. 클라이언트는 순차 페이지 조회를 사용하고 반복 커서를 거부하며 최대 50페이지에서 중단한다. 기존 v1/v2와 고객 status v10의 응답 형식을 보존하고 새 고객 status v11, 직원 detail v8을 사용한다.

접수는 기존 session/access key, 멱등키, 주소, 영업시간, 요청사항 계약을 유지한다. 매장·메뉴·구성품·음료의 활성/공개/품절 상태와 음료 수량을 서버에서 검증한다. 최대 50행, 합계 100개, 한 메뉴 수량 최대 50개를 유지한다. 음료 선택은 행당 최대 500개이며 원래 설정의 0–10개/콤보 규격을 사용한다. 메뉴, 고정 구성품, 선택 음료, 세율과 가격은 한 번의 일괄 준비로 조회·집계하고 요청 품목을 한 INSERT로 저장한다. 클라이언트가 보낸 금액·세율은 사용하지 않는다.

구성품·음료 선택 및 VAT 배분 가중치는 요청 당시 불변 스냅샷으로 저장한다. 견적과 입금 승인에서 현재 판매 가능 상태와 고정 구성 변경을 다시 검증한다. 선택 음료 수량에는 `is_total_quantity`를 사용해 콤보 수량이 두 번 곱해지지 않도록 한다. 새 콤보 주문은 세율별 VAT와 서비스 요금을 정수 VND로 반올림해 견적·입금 QR·결제·송장 금액을 일치시킨다. 일반 QR/캐셔 품목의 기존 스냅샷 및 두 자리 소수 계산과 발행 이력은 유지한다.

입금 확인은 운영의 `direct_order_record_receipt`를 사용한다. 일반 직원에게 폐쇄된 photo approval 내부 진입점의 권한은 변경하지 않는다. `process_payment` 진입점은 그대로 유지한다. 새 배달 콤보만 내부 결제의 부모 레시피 차감에서 제외하고 승인 트랜잭션 안에서 실제 구성품 레시피를 합산해 재고·원장을 일괄 반영한다. 부모 레시피가 있더라도 이중 차감하지 않는다. 재고 행 잠금 순서는 ID로 통일하고 승인 재시도는 이전 결과를 반환한다. 기존 주문·견적·결제 데이터는 갱신하지 않는다.

## 검증 및 배포

- 화면: 전송 버튼 1개, 안내 중복 제거, 음료 1/2개 선택 및 취소, 다국어·휴대폰 화면.
- SQL: 판매 가능·품절·잘못된 선택, 메뉴 커서, 선택/VAT 스냅샷, 고객/직원/견적, 실제 운영 결제 함수의 혼합 VAT, 부모 레시피 이중 차감 방지, 승인 재시도.
- PostgREST: 메뉴 응답 행·바이트·시간, 동시 주문 접수와 입금 확인의 논리 요청·결제 수, 실제 재고 변화. 격리 DB 측정값은 운영 지연 시간이나 앱 메모리 증거로 표시하지 않는다.
- 전체 검사: `bash scripts/check_repo.sh`. exact main SHA의 필수 `POS release contract` 성공 이후 공식 `scripts/deploy_pos_production.sh`로 단일 migration, Edge, 웹을 배포한다.
- 운영 확인: migration history, 새 RPC/권한, checker 함수 및 기존 payment 진입점 해시, 이전 주문·견적·결제 불변, 기존 계정 로그인, 공개 샘플 메뉴와 실제 웹 bundle을 읽기 전용으로 확인한다.
