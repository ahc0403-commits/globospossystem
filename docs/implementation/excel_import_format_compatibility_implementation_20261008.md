# Excel 업로드 서식 호환 개선 결과

작성일: 2026-10-08 · Asia/Ho_Chi_Minh  
상태: 소스 구현 및 로컬 검증 완료. 운영 배포와 운영 업로드 확인은 수행하지 않았다.

**첨부 `RM List.xlsx`를 읽지 못하게 했던 숫자 서식 오류를 해결했다. 원재료 등록은 이제 파일을 읽은 뒤 “원재료등록 시트가 없다. 현재 시트: RM List”라는 실제 양식 문제를 안내한다. 시트·열 구성과 가격 공란 7개는 별도로 보완해야 한다.**

## 구현한 변경

| 적용 대상 | 결과 |
|---|---|
| [공통 Excel 디코더](/Users/andreahn/globos_pos_system/lib/core/utils/excel_workbook_decoder.dart) | 명시적인 숫자 서식 ID가 164 미만이면 충돌 없는 사용자 서식 ID로 옮기고 정의·스타일 참조를 함께 갱신한다. 첨부의 ID 43이 이 처리로 정상 해석된다. |
| 숫자 서식 보존 | `formatCode`를 유지한다. 정의 없이 사용한 회계 숫자 서식 41~44는 검증된 숫자 서식 정의를 제공한다. 알 수 없는 서식을 일반 숫자로 바꾸지 않는다. 같은 ID의 상충하는 정의는 오류로 안내한다. |
| 기존 경로 호환 | `/xl/worksheets/...` 관계 경로 보정과 숫자 서식 보정을 한 번의 ZIP 재구성에 묶었다. 변경할 XML이 없으면 원본 바이트로 해석한다. |
| 업로드 연결 | 원재료·레시피·거래처 단가 등록을 공통 디코더로 통일했다. 기존 메뉴·메뉴 수정용 파일·Photo 수동 매출 업로드도 같은 디코더를 사용한다. |
| 오류 안내 | 손상/지원하지 않는 파일, XML 오류, 지원하지 않는 숫자 서식, 기타 해석 실패를 구분한다. 화면에 한국어·영어·베트남어 안내를 연결하고 내부 예외 원문을 표시하지 않는다. |
| 원재료 입력 안내 | 필요한 시트가 없으면 현재 시트 이름을 표시한다. 가격 공란은 행 번호와 “가격을 입력하세요”를 표시한다. 가격 0은 계속 허용한다. |
| 의존성 | 이미 잠긴 `xml 6.6.1`을 직접 의존성으로 선언했다. `excel 4.0.6` 및 다른 패키지 버전은 올리지 않았다. |

보정은 메모리 사본의 `xl/styles.xml`과 워크북 관계 XML에 한정한다. 시트 셀 값·수식·캐시·공유 문자열은 수정하지 않으며 원본 파일을 덮어쓰지 않는다. 신규 DB 조회나 행별 네트워크 요청을 추가하지 않았다. 기존 등록 검증·미리보기·저장 방식과 1,000행 제한을 유지한다. Photo 자동 수집 변경은 없다.

## 계획에서 조정한 처리 순서

[개선계획](/Users/andreahn/globos_pos_system/docs/plans/excel_import_format_compatibility_plan_20261008.md)의 최초안은 라이브러리 해석 실패 후 서식을 보정하는 순서였다. 구현에서는 **해석 전에 스타일을 검사**한다.

설치된 라이브러리는 정의 없는 미지원 서식을 debug에서는 assertion으로 거부하지만 release에서는 일반 숫자로 읽을 수 있다. 실패 후에만 보정하면 날짜 값이 release에서 조용히 숫자로 바뀔 수 있다. 사전 검사를 통해 debug와 release에서 같은 판정을 내리고, 의미를 확인할 수 없는 서식은 안내한다. 공통 디코더 실행당 라이브러리 해석은 한 번이며 재시도 루프가 없다.

## 첨부 파일에 남은 보완 사항

- 시트 이름 `RM List`를 등록 양식의 `원재료등록`에 맞추고 필수 12개 열로 작성해야 한다. 단순히 시트 이름만 바꾸면 필수 열 누락 검증에서 막힌다.
- 가격 공란은 원본 `F38`, `F112:F117`의 7개다. 가격을 확인하여 입력해야 하며 자동으로 0을 채우지 않았다.
- 원본 `VAT(%)` 열의 `G16`, `G110`은 세율 대신 세액 계산 수식이며 현재 원재료 등록 양식에서 가져오는 항목이 아니다.

차이와 가격 누락은 이미 만든 [노란 셀·설명 검토 사본](</Users/andreahn/Downloads/RM List_등록검토_20261008.xlsx>)에서 확인할 수 있다.

운영 앱은 아직 변경되지 않았다. DB·RPC·권한 변경은 없으며 push, GitHub Actions 릴리스 게이트, 운영 배포·실제 등록은 수행하지 않았다. 운영 적용은 프로젝트의 `scripts/deploy_pos_production.sh` 및 정확한 pushed head SHA의 필수 CI 검사를 거쳐야 한다.
