## 변경

- 모든 발주 가능 역할은 매장 정책 유무와 관계없이 공통 PR 화면에 진입한다.
  정책이 없거나 비활성이면 공통 화면에서 작성을 차단하며 구형 PO 생성으로 전환하지 않는다.
- 과거 발주 목록의 새 요청 버튼도 PR 화면을 연다. 기존 문서 조회·초안 편집·입고와
  명시적 PO 상세 링크는 유지한다.
- 초기 PR 진입에서 전체 거래처 품목 카탈로그 조회를 제거했다.
- 회계 계정의 매장 필터에서 재현한 가로 넘침을 수정했다.
- `20261019081922_procurement_all_store_parity.sql`은 활성 발주 계정 요구사항이 있는
  활성 매장들의 정책을 BunsikClub BT와 일치시킨다. 현재 운영 대상은 위 세 매장이다.
  UUID·로그인 코드 하드코딩 없이 매장별로 일괄 처리한다.
- 정책의 실제 변경만 버전을 올리고 이전/이후 상태를 감사 이력으로 기록한다.
  중복 계정이 있어도 매장별 한 번 처리하며 동일 SQL 재실행은 변경하지 않는다.
  기존 PR·PO·계정·매장·권한을 변경하지 않는다. 향후 신규 매장의 활성화는 명시적으로 수행한다.
- 기존 전체 다이얼로그 검사에서 발견한 `additionalTests` 인자 누락과 기존 현금 QR
  테스트 등록 누락을 보완했다. 기존 테스트·사용자 코드를 보존했다.

기존 계정·매장·PR·PO 보존, 매장별 감사 이력, 재적용 시 버전/이력 유지가 통과했다.

초기 진입은 서비스 호출 계측에서 PR 페이지 **1회**, 전체 카탈로그·구형 목록·구형 상세
각 **0회**였다. 재고 이벤트 1개는 PR 페이지 1회만 추가했다. 네트워크 지연이나

## 운영 반영에 남은 단계

`scripts/deploy_pos_production.sh`만 사용한다. 이 변경과 필요한 기존 작업이 포함된
깨끗한 커밋이 최신 `origin/main`과 일치하고, 같은 SHA의 `POS release contract`
GitHub Actions 검사가 성공해야 한다. 위 마이그레이션과 웹 앱을 함께 반영한 후
동봉 preflight/verify SQL 및 실제 계정 로그인으로 운영 결과를 확인한다.

현재 운영에서는 원래 정책 상태가 유지된다. 운영 발주 생성·승인·공급자 발송은
수행하지 않았다. 매장별 Office 담당자 roster 차이는 POS 화면 선택 원인이 아니며,
다른 매장의 Office 권한·담당자를 복제하지 않았다. 전체 저장소 검사
`scripts/check_repo.sh`와 실제 구매 전 과정의 운영 UAT는 완료 증거에 포함되지 않는다.
