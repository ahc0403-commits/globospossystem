# 매장 PR 승인 이력과 Office 구매팀 인계

매장 승인 후 PR은 `office_review`로 이동한다. 기존 매장 결재함은 현재 단계의
`mine` 목록과 최종 `approved/allocated` 분류만 제공해, 매장 승인 후 구매팀
검토 중인 문서를 자신의 결재 이력으로 찾을 수 없었다.

`request_scope=history`는 현재 상태 대신 같은 매장·시스템·계정의 보존된
승인/반려 이벤트를 일괄 조회한다. 정책 1/2의 기존 이벤트도 보존한다.
화면의 별도 `내 결재 이력`은 상태 분류를 제거하고 갱신일 내림차순과 기존
커서를 사용한다. 매장 승인 성공 후 구매팀 검토 대기와 이력 위치를 알린다.

운영 읽기 확인에서 매장 승인 3건은 실제로 `office_review`였다. Office의
등록된 구매 담당 계정으로 기존 비밀번호 로그인 후 `pos-bridge` 결재함·목록·
상세가 모두 HTTP 200이고, 같은 PR 3건에 `office_approve`가 반환됐다.
Office의 기본 구매 승인 메뉴는 자체 문서 목록을 열고 있어 별도 수정한다.
운영 PR을 새로 생성하거나 실제 승인/반려 명령을 수행하지 않았다.

## 검증과 조회 비용

- 관련 Flutter 위젯/기본 라우팅 17개 테스트 및 전체 정적 분석 통과.
- 전체 격리 구매 SQL 검증 통과: 실제 매장 승인 → 현재 목록 제외 → 본인
  이력 유지 → Office 구매팀 결재함의 동일 PR → 구매팀 최종 승인 후 이력 유지.
  멱등 재시도, 다른 계정 이력 제외, 교차 매장 거부, 알 수 없는 필터 거부 포함.
- 목록은 기존 단일 RPC, 페이지 기본 20/최대 50건을 유지한다. 이력 이벤트를
  매장·계정으로 한 번 사전 조회하고 집합으로 연결한다. 항목별 원격 호출을
  추가하지 않는다. 조건부 이벤트 인덱스를 추가했다. 동시 폴링은 기존 요청
  병합을 유지한다. 운영 성능과 UI 검증은 배포 후 별도 기록한다.
