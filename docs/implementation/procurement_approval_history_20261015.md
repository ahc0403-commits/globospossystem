# 매장 PR 승인 이력과 Office 구매팀 인계

매장 승인 후 PR은 `office_review`로 이동한다. 기존 매장 결재함은 현재 단계의
`mine` 목록과 최종 `approved/allocated` 분류만 제공해, 매장 승인 후 구매팀
검토 중인 문서를 자신의 결재 이력으로 찾을 수 없었다.

`request_scope=history`는 현재 상태 대신 같은 매장·시스템·계정의 보존된
승인/반려 이벤트를 일괄 조회한다. 정책 1/2의 기존 이벤트도 보존한다.
일반 `history` 조회 계약은 유지한다. 매장 화면은 첨부 요구에 따라
승인대기·승인완료·반려 세 탭을 제공하고, 승인완료에는 자신의 매장 승인 후
`office_review`로 이동한 PR도 포함한다. 최신 작성일과 ID 내림차순 커서를
사용한다. 재제출은 현재 개정을 대기로 이동시키며 과거 반려 이벤트를 보존한다.
매장 승인 성공 후 구매팀 검토 대기와 승인완료 탭 위치를 알린다.

운영 읽기 확인에서 매장 승인 3건은 실제로 `office_review`였다. Office의
등록된 구매 담당 계정으로 기존 비밀번호 로그인 후 `pos-bridge` 결재함·목록·
상세가 모두 HTTP 200이고, 같은 PR 3건에 `office_approve`가 반환됐다.
Office의 기본 구매 승인 메뉴는 자체 문서 목록을 열고 있어 별도 수정한다.
운영 PR을 새로 생성하거나 실제 승인/반려 명령을 수행하지 않았다.

## 검증과 조회 비용

- 관련 Flutter 위젯/기본 라우팅과 KO/EN/VI 반응형 레이아웃 검증을 수행한다.
- 전체 격리 구매 SQL 검증 통과: 실제 매장 승인 → 현재 목록 제외 → 본인
  이력 유지 → Office 구매팀 결재함의 동일 PR → 구매팀 최종 승인 후 이력 유지.
  멱등 재시도, 다른 계정 이력 제외, 교차 매장 거부, 알 수 없는 필터 거부 포함.
- 목록은 기존 단일 RPC, 페이지 기본 20/최대 50건을 유지한다. 이력 이벤트를
  매장·계정으로 한 번 사전 조회하고 집합으로 연결한다. 항목별 원격 호출을
  추가하지 않는다. 조건부 이벤트 인덱스를 추가했다. 동시 폴링은 기존 요청
  병합을 유지한다. 운영 성능과 UI 검증은 배포 후 별도 기록한다.

## 첨부 화면 구현

스토어 매니저 결재 화면에서 운영 지표·담당자, 과거 발주 검토, 내 결재 대기
필터를 제거했다. 구매 유형/검색/기간은 유지한다. 우측 상단에 재고 조회와
구매요청 작성 버튼을 순서대로 배치한다. 모바일과 큰 글자는 줄바꿈한다.
재고 조회는 클릭할 때 별도의 검색/커서 목록으로 읽고 닫아도 PR을 다시 읽지
않는다. PR 목록은 요약만 요청하고, 품목 카탈로그는 재고/작성/수정 시에 읽는다.
상위 재고 화면의 기존 권한·정책 부트스트랩 호출은 유지한다.

요청 카드는 번호·작성일·필요일·품목 수, 기록된 요청자 계정/역할, 요청 사유,
상세 보기로 구분한다. 예시 이름이나 직원 매핑을 만들지 않는다. 승인완료
건의 다음 단계는 매장 승인 완료·구매팀 검토 대기로 명확히 표시한다.
취소는 반려로 바꾸지 않으며 추가 이력 메뉴에서 조회한다. 삭제된 화면 요소의
데이터와 감사 이벤트, 기존 정책 1/2 문서는 보존한다.

SQL 회귀는 매장 승인 직후 승인완료 건수/목록, 동일 검색 범위의 탭 건수,
카탈로그 생략, 최신 요청일/동률 ID 커서의 중복·누락, 실제 반려/재제출의
상호 배타적인 탭 상태를 검증한다. 위젯은 390px(1.5배 글자)/1440px와
KO/EN/VI에서 요청자·사유·품목·버튼 및 지연 재고 조회를 검증한다.
