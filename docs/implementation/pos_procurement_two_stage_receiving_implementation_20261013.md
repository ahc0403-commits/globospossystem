## 입고와 업체 전달 문서

| 상황 | 처리 |
|---|---|
| 모든 원료의 원래 PO 수량과 누적 합격 입고 수량 일치 | 재고 반영 후 전량 입고 확인서 데이터 저장 |
| 부족·초과·불합격 포함 | 실제 합격 수량만 재고 반영 후 PO 대비 수량 차이서 데이터 저장 |
| 전량 미입고 | 수량 0으로 검수 기록과 차이서 저장, 재고 증가 없음 |
| 파일 생성·업로드 실패 | 확정된 입고를 되돌리지 않고 문서만 다시 생성 |

비교는 각 PO 원료별로 하며, 서로 다른 원료의 초과와 부족을 상쇄하지 않는다. 문서는 이전/이번/누적 수량과 부족·초과·불합격, 원료코드, 검수자·일시를 포함한다. 업체 문서에는 가격이 없다. 취소·이관으로 닫힌 잔량은 실제 전량 입고로 판정하지 않는다.

검수 성공 후 PDF 생성·저장을 연결했다. 생성·다운로드는 업체 전달 완료로 표시하지 않는다. 실제 전달 후 담당자가 채널·수신처/증빙과 파일 해시를 기록한다. 업체로 자동 메시지를 보내는 연동은 추가하지 않았다. 파일은 private Storage에 저장하며 덮어쓰기·삭제를 제한한다. 새 파일 해시로 재생성하면 새 파일의 전달 상태는 대기로 돌아가고 기존 전달 이벤트는 보존한다.

## 다음 발주 연결

부족 원료는 다음 PR의 상단에 자동 추가한다. 동일 원료·업체의 여러 부족분을 묶되 원래 PO별 출처와 수량을 보존한다. 화면과 PR·PO 출력에서 일반 신규 품목보다 먼저 표시하고 부족 수량·원래 PO 번호를 명시한다.

예약은 PR 저장 시, 실제 이관은 다음 PO 발행 시 확정한다. 원래 미입고 잔량을 두 PO에 중복으로 남기지 않고 양쪽 PO 원료 행을 연결한다. 원래 PO의 표시 결과는 `일부 입고 · 잔량 이관`이며 실제 입고 확인서로 바뀌지 않는다. PO 발행은 재고나 지급을 실행하지 않는다. 기존 Office의 입고·Invoice·지급 검증을 유지한다.

예: 원래 10박스 중 7박스 입고 → 부족 3박스. 신규 필요량 2박스를 더하면 다음 PO는 5박스다. 발행 전에 1박스가 추가 입고되면 부족분을 2박스로 다시 확인하고 신규 필요량 2박스를 유지해 총 4박스로 수정·승인한다. 저장·승인·발행 중 최신 잔량이나 다른 예약과 충돌하면 거래 전체를 거부한다. 반려된 요청을 다시 열면 실제 입고를 반영해 예약 수량을 갱신한다.

격리된 로컬 PostgreSQL에서 승인 순서, 자기 승인 차단, 코드 검색, 승인·Office 회계 스냅샷 보존, 부분/전량 미입고, 추가 입고 후 예약 수정, 다음 PO 이관, 최종 전량 입고, 원래 응답의 재시도, 다른 매장 접근 차단을 검증했다. 동시 입고 재시도는 재고를 한 번만 증가시키며, 같은 부족분을 경쟁 예약하면 하나만 성공한다.

검색 페이지는 최대 200품목, 선택 품목/부족 출처는 최대 200개, PR·입고는 최대 200행이다. 검색 요청은 선택창당 동시 1개이며 약 300ms 입력 지연을 적용한다. 검색은 PR/PO 목록·건수 재조회 없이 처리한다. 입고 SQL의 원료별 반복 조회/집계를 일괄 처리로 바꿨다. 선택 상세는 최근 20회 입고, 문서 20개, 승인 이력 100개를 반환하고 누적 수량은 모든 확정 입고를 집계한다.

## 운영 반영

세 additive migration을 시간순으로 적용하고 앱을 함께 반영한다. 진행 중인 미승인 요청은 정책 3으로 전환하며 버전 충돌 시 재조회한다. 승인 완료·발행 이력은 보존한다. 각 migration의 self-verifying 경계 검사는 소스/DDL 확인이며 실제 역할별 인수 검사를 대신하지 않는다.

운영 배포는 기존 `scripts/deploy_pos_production.sh`와 정확한 pushed head SHA의 필수 GitHub Actions 성공을 거쳐야 한다. 이번 구현 작업은 운영 DB 변경, 실제 계정으로 발주·입고, 외부 업체 발송 또는 배포를 실행하지 않았다. 실제 Office 구매담당자 화면, Storage 권한, 매장 입고와 업체 전달은 운영 인수에서 확인한다.

### 최신 main 통합 보완

기존 제출 입고 잠금과 충돌하는 계산은 권한을 확인한 정책 3의 private verifier 안에서 해당 입고 ID에만 한시적으로 허용한다. 성공·예외 시 범위를 복구하며 일반 제출 내역 수정, 확정 기록 변경, 과거 독립 검증자 계약을 유지한다. 기존 제출된 정책 3 입고의 확정 버튼과 합격 수량을 유지하고 원료 담당자의 숨긴 단가는 전송하지 않는다. 서버도 해당 역할의 정책 3 단가 입력을 거부한다. 실패한 입력은 입고·재고를 남기지 않고 재시도·불변 문서·부족분 예약 경쟁을 SQL과 위젯으로 검사했다.
