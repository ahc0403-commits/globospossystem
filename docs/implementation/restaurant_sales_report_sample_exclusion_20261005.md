# 샘플매장 매출 신고 제외 — 2026-10-05

아래 상태와 배포 제한은 최초 구현 시점의 기록이다. 후속 릴리스의 운영 적용 및 검증 결과는 배포 보고서에 별도로 기록한다.

최초 상태: 소스 수정·로컬 검증 완료. 운영 DB 마이그레이션 적용, 웹 배포, 운영 화면 검증은 미실행이다.

## 원인과 운영 확인

운영 POS DB를 읽기 전용으로 확인했다. `BunsikClub SAMPLE`은 별도 비세무 법인
`PENDING_SAMPLE_STORE_TAX_PROFILE`에 정상 연결돼 있다. 2026-10-05 HCM 날짜 기준
완료 주문의 매출 결제는 1건, 189,000 VND다.

기존 신고 RPC는 샘플을 `is_sample_entity`로 표시해 별도 법인으로 반환한다.
화면은 실법인을 먼저 선택하지만 샘플도 선택 목록에 포함한다. 샘플 표시 여부는
다운로드 준비 조건에 없어서 샘플 MISA 엑셀도 생성할 수 있었다. 별도 법인 분리는
실법인과의 합산을 막지만 신고 대상 자체에서 제외하지 않는다.

## 수정

- 새 마이그레이션은 기존 샘플 매장 ID, 현재 샘플 법인, 매출 당시 샘플 판매자 법인을 신고 RPC에서 제외한다. 과거 결제와 주문은 삭제하거나 변경하지 않는다.
- 기존 함수의 두 조회 조건만 변경해 현재 VAT 품목·스냅샷·조회시간·권한 계약을 보존한다. 기존 단일 법인 RPC도 같은 결과를 사용한다.
- 클라이언트의 통합 신고 목록에서 샘플을 제외하고 단독/통합 MISA 엑셀 생성도 차단한다.

## 검증과 운영 반영 제한

수정 전 샘플 목록 노출·샘플만 있는 날짜·샘플 다운로드 회귀 테스트 3개가 실패했다.
수정 후 관련 Flutter 테스트 42개, 신고 SQL 회귀 검증, 관련 파일 정적 분석이 통과했다.
SQL 검증은 격리 Docker DB에서 실제 마이그레이션을 두 번 적용하며 매장 이름·법인
변경, 과거 법인, 실매출 보존, 샘플만 있는 날짜, 기존 RPC를 확인했다.

`scripts/deploy_pos_production.sh --db-only ... --dry-run --yes`의 preflight는
`Refusing to deploy dirty worktree`로 차단됐다. 현재 작업 폴더에 다른 작업의 미커밋
변경이 있어 `CLAUDE.md`의 깨끗한 exact-main·필수 GitHub 검사 게이트를 충족하지
않는다. 배포 게이트를 우회하지 않았으며 운영 변경은 수행하지 않았다.
